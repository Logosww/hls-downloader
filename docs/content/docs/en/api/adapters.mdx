Adapter-specific fields are passed via `HlsDownloader` constructor `options` / `setOptions`, or per-call on `download()`. They are merged with per-call options taking precedence.

<Callout type="info" title="Transmux first">
  Across adapters, **default downloads transmux/remux without re-encoding**. BrowserAdapter uses
  [hls-transmux](https://github.com/Logosww/hls-transmux) WebAssembly for transmux and Mediabunny
  WebCodecs for `transcode`; NodeAdapter initializes native FFmpeg only when needed.
</Callout>

## BrowserAdapter

```ts
import { BrowserAdapter } from '@hls-downloader/adapters/browser';
```

Ordinary downloads use [hls-transmux](https://github.com/Logosww/hls-transmux) WebAssembly. `download()` returns a classic fast-start MP4; `downloadToStream()` emits fragmented MP4 chunks.

Transcoding uses Mediabunny and WebCodecs without `@ffmpeg/ffmpeg`. BrowserAdapter accepts the `h264`, `hevc`, and `vp9` presets with optional `videoBitrate` and `audioBitrate`. Unsupported browser encoder configurations reject with an explicit error.

Reference CPU micro-benchmarks (8-segment fixture, Chrome 150 / macOS, median of 3): transmux ≈ **5.0×** vs Mediabunny remux; H.264 transcode ≈ **2.2×** vs multi-threaded `ffmpeg.wasm`. See [Adapters guide](/guide/adapters#performance-reference).

### `download()` result

| Field           | Type     |
| --------------- | -------- |
| `blobURL`       | `string` |
| `totalSegments` | `number` |

### Browser media request context

`options.browserRequest` supplies BrowserAdapter defaults. `parseHls`, `getPosterUrl`, `download`, `downloadToStream`, and `downloadToWritable` accept a per-call `browserRequest` that **replaces the entire instance configuration**. `{}` selects native fetch defaults; omitted values inherit the instance configuration. NodeAdapter does not support this option.

The optional `fetch(url, init): Promise<Response>` performs **one attempt** and may asynchronously prepare extension context before sending. It receives the actual URL, existing headers (including Range), credentials and cancellation signal. Return a standard Response preserving status, headers, streaming body and final URL; honor the signal during preparation, transmission and body consumption. Synthetic responses without a final URL use the requested URL as the relative-resource base. The library retains its retry policy, retries failed body reads without publishing partial bytes, and discards late results after cancellation. Do not add another retry loop inside the transport.

All media reads, including posters and transcoding, use the selected transport. WASM uses its independent local resource loader. Without configuration, fetch and credential defaults remain unchanged. HTTP 401/403 retain status metadata without retries; network failures and cancellation remain distinguishable. Poster transport failures now reject with structured errors; undecodable video still returns `undefined`.

Each operation snapshots the request configuration and headers. Browser playlist and poster results are **not cached between public calls**, including calls on the same instance; changing login state takes effect on the next call. `clearCache()` remains available and is a no-op for BrowserAdapter. Repeated parsing/poster calls therefore perform new requests. Transport closures must themselves keep a stable context for an in-flight operation.

```ts
import { HlsDownloader } from '@logosw/hls-downloader/core';
import { BrowserAdapter } from '@logosw/hls-downloader/adapters/browser';

const mediaOrigin = 'https://media.example.com';
const downloader = new HlsDownloader({
  adapter: BrowserAdapter,
  options: {
    browserRequest: {
      credentials: 'include',
      async fetch(url, init) {
        const trusted = new URL(url).origin === mediaOrigin;
        const headers = new Headers(init.headers);
        if (trusted) headers.set('Authorization', 'Bearer <token>');
        init.signal?.throwIfAborted();
        return fetch(url, {
          ...init,
          headers,
          credentials: trusted ? init.credentials : 'omit',
          redirect: 'error',
        });
      },
    },
  },
});

await downloader.parseHls({ url: mediaOrigin + '/video.m3u8' });
await downloader.parseHls({ url: mediaOrigin + '/public.m3u8', browserRequest: {} });
```

In this example the transport permits credentials only for the chosen origin and rejects redirects. Applications that allow redirects must enforce their own destination policy; native fetch does not expose every intermediate redirect to the callback. Existing explicit `headers` apply to media requests as before, so supply target-specific credentials in the transport instead of global headers.

The extension owns permissions, tab/source associations, asynchronous rule setup and cleanup. Cookie, Referer and Origin cannot reliably be replayed using ordinary headers. Browser cookie policies, partitioned cookies and site authorization can still prevent downloads. The library neither reads browser cookies nor installs Chrome-specific request rules. Avoid logging credentials or throwing exceptions that contain them.

For WXT Manifest V3 pages, import the public `/core` and `/adapters/browser` subpaths. Production builds bundle the shipped WASM locally; the extension CSP must allow `script-src 'self' 'wasm-unsafe-eval'`. WASM initialization is independent of media transport and does not receive site credentials. No resource-path override is required by the acceptance build.

## NodeAdapter

```ts
import { NodeAdapter } from '@hls-downloader/adapters/node';
```

Ordinary downloads use a **native transmux path**. **Native FFmpeg is not initialized** unless one of the FFmpeg scenarios below applies.

### When FFmpeg loads

| API              | Loads FFmpeg?    | Condition                                                                             |
| ---------------- | ---------------- | ------------------------------------------------------------------------------------- |
| `parseHls()`     | No               | —                                                                                     |
| `init()`         | No               | —                                                                                     |
| `download()`     | **No** (default) | Omit `transcode` / `globalOptions.transcode` and `aria2.enabled` → transmux only      |
| `download()`     | **Yes**          | A `transcode` options object, `globalOptions.transcode`, **or** `aria2.enabled: true` |
| `getPosterUrl()` | **Sometimes**    | Only if lightweight segment extraction fails and an FFmpeg-based fallback is needed   |

### `download()` result

| Field           | Type     |
| --------------- | -------- |
| `filePath`      | `string` |
| `totalSegments` | `number` |

### Adapter-specific options

| Field   | Type     |
| ------- | -------- |
| `aria2` | `object` |

Segment downloads use the built-in HTTP stack by default. Set `aria2.enabled` to `true` to use [aria2](https://aria2.github.io/) (`aria2c` CLI + session file).

When `aria2.enabled` is `true`, aria2 must be installed. Custom request headers are written into aria2’s session file (`header=Name: value` per URI).

#### `aria2` object (`NodeAdapterAria2Options`)

| Field                    | Type       |
| ------------------------ | ---------- |
| `enabled`                | `boolean`  |
| `path`                   | `string`   |
| `maxConcurrentDownloads` | `number`   |
| `maxConnectionPerServer` | `number`   |
| `split`                  | `number`   |
| `minSplitSize`           | `string`   |
| `extraArgs`              | `string[]` |

When `maxConcurrentDownloads` is omitted, the effective concurrency follows `downloadConcurrency` on each `download()` call (or `globalOptions.download.concurrency`).

### Platform Support

The native addon must match your operating system and Node.js ABI. Pre-built binaries are published for common platforms.

## Writable output

| Capability          | Browser | Node |
| ------------------- | ------- | ---- |

| `alternateAudio`    | true    | true |
| `subtitleExport`    | true    | true |
| `resumableDownload` | false   | true |

Use `downloadToWritable()` for bounded media buffers and an asynchronous destination. Existing callback streaming behavior is unchanged.

Node recovery requires per-call `resume: { directory }` and plain VOD file output. It cannot be combined with transcoding, enabled aria2, or streaming APIs. See [download recovery](./hls-downloader).

## AES-128 VOD

External-audio output with initial track offsets is verified for file/Blob playback. Chromium MSE ignores leading empty edits; an MSE host must map timestamps per track instead of appending these multiplexed bytes unchanged to one SourceBuffer. The SDK does not provide that MSE mapping.

BrowserAdapter and NodeAdapter automatically recognize AES-128 in the selected media playlists. Supported inputs are finite TS/fMP4 VOD with AVC/HEVC video and AAC-LC audio, including clear/encrypted transitions, key rotation, encrypted MAPs and one selected external audio track. `download()` produces classic MP4; callback and writable output produce fMP4. Browser playback still depends on the device's codec support.

By default, identity/version-1 keys use the same headers, retry policy, cancellation and Browser `browserRequest` transport/credentials as media requests. A key must contain exactly 16 bytes. Key responses are read with a 17-byte limit; invalid lengths are not retried.

```ts
await downloader.downloadToWritable(
  {
    url: 'https://example.com/video.m3u8',
    decryption: {
      keyResolver: async (request) => {
        const response = await fetch(request.uri, { signal: request.signal });
        if (!response.ok) throw new Error('Key request failed');
        return { key: new Uint8Array(await response.arrayBuffer()), expiresInMs: 60_000 };
      },
    },
  },
  writable,
);
```

`decryption` is a per-operation option for download, stream and writable methods:

| Field | Contract |
| --- | --- |
| `keyResolver` | Replaces the HTTP provider. Return `{ key: Uint8Array, version?: string, expiresInMs?: number }` or `null`. Only `null` permits trying another declared key-format candidate. A throw/rejection fails safely without exposing its message or triggering HTTP fallback. |
| `keyFormats` | Ordered `{ format: string, versions: readonly number[] }[]`; defaults to identity/version 1. Declare custom formats explicitly. |
| `encryptedRanges` | Defaults to `'reject'`. `'complete-resources'` attests that each range is a complete independently encrypted/padded resource. A 206 response with exact Content-Range and length is required. |
| `limits` | Positive safe integers; defaults listed below. Resource limits bound source reads, not total process or Blob memory. |

The resolver receives `operationId`, `inputId`, `resourceKind`, `uri`, `method`, `keyFormat`, `keyFormatVersions`, `originalSequence`, `epoch`, `generation`, `declaration`, `resolveRevision`, `refreshGeneration`, `refreshReason` and a request-specific `signal`. Protocol integers are decimal strings. `expiresInMs` is a nonnegative safe integer relative lifetime; zero is immediately expired. Cancellation aborts pending resolver requests, and late results are discarded. Caches are operation-scoped even when two calls use the same `operationId`.

Default `limits`: `manifestBytes = 4 MiB`, `resourceBytes = 16 MiB`, `waitingBytes = 32 MiB`, `resources = 2`, `keyRequests = 2`, `cachedKeys = 8`, `keyWaiters = 2`. `waitingBytes` must be at least `resourceBytes`. The manifest limit also applies when selecting playlists for ordinary downloads; increase `manifestBytes` for large finite playlists. Configuring `decryption` explicitly selects the typed finite-input path even for clear input. `resources` controls keyed concurrency; legacy `downloadConcurrency` continues to apply to the existing clear path.

`capabilities.aes128` indicates this finite profile; `capabilities.decryption` describes methods, containers, codecs, external audio and the absence of encrypted recovery. GCM, encrypted resume, transcoding, aria2 and encrypted WebVTT remain unsupported. Use `startRecording()` for supported Live/EVENT inputs. Discontinuities require explicit `timeline`; finite sample encryption is described below. Unsupported playlist combinations are rejected before key/media work; container and codec validation requires reading media.

Errors distinguish `KEY_UNAVAILABLE`, `KEY_RESOLUTION_FAILED`, `KEY_INVALID`, `KEY_EXPIRED`, `ENCRYPTION_INVALID`, `DECRYPT_FAILED`, `MEDIA_INVALID` and `RESOURCE_LIMIT_EXCEEDED`. CBC decryption is not authenticated encryption. A wrong key is not guaranteed to be detectable. Resolver messages, key bytes and key versions are excluded from public errors/events.

`DECRYPTION_PROGRESS` carries `payload.decryption`: per-input discovered/committed counts plus separate media/MAP downloaded, decrypted and ready counters, all as decimal strings. Clear resources do not increase decrypted counts. Committed counts are not recovery checkpoints. The public completion event is emitted only after the destination closes successfully.

## Finite sample encryption

| Container / 容器 | Method | Scheme | Codec |
| --- | --- | --- | --- |
| TS | SAMPLE-AES | sample CBC | AVC, AAC-LC |
| fMP4 | SAMPLE-AES | cbcs | AVC, HEVC, AAC-LC |
| fMP4 | SAMPLE-AES-CTR | cenc | AVC, HEVC, AAC-LC |

These profiles are selected automatically, including without `timeline`. They support one replacement external audio track, file/Blob, callback stream, writable, ranges and split outputs. `capabilities.decryption.profiles` is the combination matrix; do not infer a Cartesian product from the top-level lists.

`HlsKeyRequest.method` includes all three methods; optional `kid` is 32 lowercase hexadecimal characters. A resolver returns the same 16-byte binary key response and retains the existing TTL, unavailable and cancellation semantics. Only configured identity HTTP or caller-provided raw keys are supported; no license/CDM exchange is implemented. `decryption.limits.samples` defaults to 65,536 per resource; the container parser also imposes a 65,536-entry ceiling. Other resource/key defaults remain unchanged. CBC/CTR cannot authenticate every incorrect key.

TS HEVC SAMPLE-AES, TS SAMPLE-AES-CTR, Packed AAC, arbitrary ciphertext slices, GCM, recovery, transcoding, aria2 and encrypted subtitles remain unsupported. The supported cenc/cbcs container metadata profile follows [hls-transmux 0.8.0](https://github.com/Logosww/hls-transmux/blob/8d6c54f/docs/sample-encryption.md).

## Continuous recording

`startRecording()` returns a control handle immediately. Use it for Live/EVENT recording or a pausable finite VOD operation; existing `download*()` methods remain finite-only. Recording starts at the beginning of the first available playlist window. Variant and optional replacement audio selection are fixed for the operation.

```ts
const recording = downloader.startRecording({
  url: 'https://example.com/live.m3u8',
  output: { type: 'writable', writable: destination },
  onEvent(event) {
    if (event.type === 'progress') console.log(event.input.committed);
  },
});
// Called by your application's Stop button:
recording.stop();
const { report } = await recording.result;
```

The handle has `operationId`, read-only `state`, `result`, `stop()`, `cancel()`, `pause()`, `resume()`, `endInput('primary' | 'audio')`, and `restartInput(inputId, { generation, url? })`. Initialization errors reject `result`. Stop closes admission and drains accepted media; cancel rejects with `ABORTED`. `pause()` acknowledges a processing boundary and is supported only for finite non-EVENT VOD. Live/EVENT pause rejects with `RECORDING_FAILED` / `PauseUnsupported` without failing the recording. Resume stays within the same operation; no durable recording checkpoint is provided.

Each input ends independently on ENDLIST or `endInput()`. A recording completes after all inputs end, an explicit stop, or `durationLimit`. Restart requires a strictly increasing decimal-string generation and an active session. It seals and drains the old generation before admitting the new source. It does not change rendition selection or automatically repair failed recordings. Clock/PDT evidence or generation-scoped anchors must establish the timeline; ambiguous alignment fails.

| Output | Runtime | Result and format |
| --- | --- | --- |
| `{ type: 'writable', writable }` | Both | Backpressured fMP4; SDK closes the destination |
| `{ type: 'writables', acquire }` | Both | Async `(output) => WritableStream`; supports splitting |
| `{ type: 'blob', maxBytes, format? }` | Browser | `result.blob`; explicit positive capacity required |
| `{ type: 'file', path, format? }` | Node | `result.filePath`; existing destinations are never replaced |
| `{ type: 'files', acquire, format? }` | Node | Async `(output) => path`; supports splitting |

`format` is `'mp4'` (default) or `'fmp4'` for Blob/files. Writable output is always fMP4. `acquire` receives an output index and track information. Single destinations and Blob output reject splitting. Public completion and output events follow successful writable close; close rejection is `OUTPUT_WRITE_FAILED`. Native files use same-directory temporary storage and hard-link publication, requiring filesystem hard-link support. Failures remove unfinished native outputs and preserve previously completed files or closed writable outputs.

Recording accepts `headers`, `signal`, `maxRetry`, `variant`, `audio`, and `decryption`; Browser also accepts `browserRequest`. It supports clear TS/fMP4, complete-resource AES-128, TS AVC/AAC-LC SAMPLE-AES, and fMP4 AVC/HEVC/AAC-LC cenc/cbcs, with the existing sample-protection restrictions. `capabilities.recording` describes output and lifecycle support. Global transcoding is not applied; explicit transcoding, aria2 and resume options are rejected.

`durationLimit: { ticks, timescale }` uses media presentation time and drains accepted work, so it may overshoot. `timeline.range` selects a decodable range; reports give the actual range. `timeline.gapPolicy` defaults to `'preserve'` and supports `'collapse'`; `timeline.changePolicy` defaults to `'fail'` and supports `'split'`. `missingSegments` defaults to `'fail'`; `'skip'` and `'split'` handle declared GAP slots only, never network/key/demux failures. `timeline.tailDuration` explicitly supplies missing tail-duration evidence. `timeline.anchors` entries contain `inputId`, decimal-string `generation` and `epoch`, and exact `source` / `presentation` times.

`limits` defaults: `queuedDescriptors: 128`, `queuedMetadataBytes: 4194304`, `historyEntries: 128`, `samples: 65536`, `sampleBytes: 67108864`, `probeSegments: 2`, `maxSkew: { ticks: '30', timescale: 1 }`, and `inputTimeoutMs: 30000`. Existing `decryption.limits` separately bound manifests, resources and key work. Oversized atomic windows fail with `RESOURCE_LIMIT_EXCEEDED`; increase the relevant limits explicitly. Refresh requests are sequential per input and respect admission backpressure; changed playlists wait one target duration and unchanged playlists half a target duration. Exhausted HTTP retries fail the operation. Sequence rollback, rewrites, missing slots and lost KEY/MAP continuity are not silently skipped or restarted.

Events include `state`, `progress`, `mapping`, `gap`, and `output`. Reports and events use decimal strings for wide integers, and input totals are `null`. `report` contains cumulative counters, requested/actual ranges, bounded recent mappings/outputs, peaks and `historyTruncated`. Keep your own bounded or persistent event log if every output is needed. Errors expose `reason`, recent `completedRecordingOutputs`, and `recordingHistoryTruncated`; these are diagnostics, not recovery checkpoints. Event handlers are synchronous observers; returned promises are not awaited.

The streaming engine and SDK history are bounded. Blob bytes, classic MP4 indexes/copies, caller-held snapshots and event logs are separate costs; `maxBytes` is not a process-memory limit. No LL-HLS partial segments, adaptive rendition switching, multiple audio tracks, subtitle mux, Packed AAC, GCM, transcoding, aria2 or persistent continuous recovery are supported.

## Multi-track capability

`capabilities.multiTrack` describes the new entries only: up to 32 media inputs (one primary plus 31 selected audio inputs), 32 wvtt subtitle tracks, VOD/Live/EVENT, ranges, split output and VOD pause. Its `decryption.profiles` includes Packed AAC-LC clear/resource AES-128/AAC SAMPLE-AES support; Packed AAC SAMPLE-AES-CTR is unsupported. TS/fMP4 retain the documented encryption profiles. Blob memory is explicitly bounded; native classic indexes grow with sample count. Transcoding, aria2, persistent resume, LL-HLS and encrypted subtitles remain unsupported. Existing `capabilities.decryption` and single-input entries do not gain Packed AAC support. See [multi-track API](/api/hls-downloader#fixed-multi-track-downloads-and-recording).
