---

The main facade class for downloading HLS streams. Imported from `@hls-downloader/core`.

<Callout type="info" title="Default download path (transmux)">
**Ordinary `download()` keeps source codecs and transmuxes to MP4.** BrowserAdapter uses [hls-transmux](https://github.com/Logosww/hls-transmux) WebAssembly; NodeAdapter uses its native Rust path.

Re-encoding is opt-in via `transcode` — see [Adapter API](/api/adapters). BrowserAdapter loads its hls-transmux WASM module in `init()`; NodeAdapter is a no-op (FFmpeg loads on demand). `parseHls()` never starts those engines.

</Callout>

## Constructor

```ts
new HlsDownloader({
  adapter,
  options?,
  onEvent?,
})
```

| Parameter | Type                            | Description                                                                                 |
| --------- | ------------------------------- | ------------------------------------------------------------------------------------------- |
| `adapter` | `BrowserAdapter \| NodeAdapter` | The adapter to use                                                                          |
| `options` | `GlobalOptions<T>`              | Default options (see below). Merged into each `parseHls` / `download` / `getPosterUrl` call |
| `onEvent` | `(event, payload?) => void`     | Event callback for tracking progress and errors                                             |

## Properties

### `isInit`

```ts
get isInit(): boolean
```

Whether the adapter has been initialized. Returns `true` after `init()` resolves.

### `globalOptions`

```ts
get globalOptions(): GlobalOptions<T> | null
```

The current default options, or `null` if none were set.

## GlobalOptions

Exported from `@hls-downloader/core` as `GlobalOptions<T>`. The shape depends on the adapter type `T`.

| Field                | Type                                 | Description                                                  |
| -------------------- | ------------------------------------ | ------------------------------------------------------------ |
| `download`           | `HlsDownloaderGlobalDownloadOptions` | Default fetch / download settings (excluding per-call `url`) |
| `transcode`          | `HlsDownloaderTranscodeOptions`      | Default transcode settings                                   |
| _(adapter-specific)_ | —                                    | See [Adapter API](/api/adapters)                             |

### `download` object

| Field         | Type                     | Description                            |
| ------------- | ------------------------ | -------------------------------------- |
| `headers`     | `Record<string, string>` | Default request headers                |
| `concurrency` | `number`                 | Default concurrent segment downloads   |
| `maxRetry`    | `number`                 | Default max retry attempts per segment |

Per-call `download({ downloadConcurrency })` overrides `download.concurrency`.

## Methods

### `init()`

```ts
async init(): Promise<void>
```

Initialize adapter state. BrowserAdapter loads its WASM module (transmux engine) here — this is the main startup cost on the browser, so callers may want to invoke `init()` ahead of time (e.g. on page load) rather than letting it block the first `download()` / `downloadToStream()`. NodeAdapter is a no-op (FFmpeg loads on demand). The call is idempotent — repeated invocations share the same promise.

`download()` and `downloadToStream()` automatically call `init()` if not yet initialized. `parseHls()` and `getPosterUrl()` do **not** trigger `init()` and work without initialization.

### `setOptions()`

```ts
setOptions(options: GlobalOptions<T>): void
```

Replace the default options. Accepts the same shape as the constructor `options`.

### `parseHls()`

```ts
async parseHls(options: HlsDownloaderFetchOptions): Promise<ParseHlsResult>
```

Parse an HLS playlist without downloading segments. Merges `options` with `globalOptions.download` (headers only).

Returns a `ParseHlsResult`:

- `{ type: 'playlist', data: Playlist[] }` — master playlist with variant streams
- `{ type: 'segment', data: Segment[] }` — media playlist with segments
- `{ type: 'error', message: string }` — parse error

| Option    | Type                     | Description      |
| --------- | ------------------------ | ---------------- |
| `url`     | `string`                 | HLS playlist URL |
| `headers` | `Record<string, string>` | Request headers  |

### `download()`

```ts
async download(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions & Partial<AdapterOptions>
): Promise<DownloadResult>
```

Parse, download all segments, and merge them into a single file. On success, **`BrowserAdapter`** resolves to `{ blobURL, totalSegments }`; **`NodeAdapter`** resolves to `{ filePath, totalSegments }`. On failure, the promise rejects.

**By default (no `transcode`)**, adapters use the transmux path and keep source codecs. Passing `transcode` opts into re-encoding: BrowserAdapter uses WebCodecs; NodeAdapter uses FFmpeg.

Merges per-call options with `globalOptions` (per-call wins).

| Option                | Type                            | Description                                                                                                                                                   |
| --------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`                 | `string`                        | HLS playlist URL                                                                                                                                              |
| `headers`             | `Record<string, string>`        | Request headers                                                                                                                                               |
| `filename`            | `string`                        | Output filename without extension. The extension is resolved internally from the output container (`mp4` by default, `webm` for `vp9`, or `transcode.format`) |
| `maxRetry`            | `number`                        | Max retry attempts per segment                                                                                                                                |
| `downloadConcurrency` | `number`                        | Concurrent segment downloads                                                                                                                                  |
| `transcode`           | `HlsDownloaderTranscodeOptions` | Transcode with WebCodecs in BrowserAdapter or FFmpeg in NodeAdapter. Omit for default transmux/remux                                                          |
| `signal`              | `AbortSignal`                   | Cooperative cancellation. When the signal aborts, the download promise rejects with an `AbortError`                                                           |
| `variant`             | `VariantSelectOptions`          | Master-playlist variant selection preferences. Omit for default (highest resolution → bandwidth)                                                              |
| _(adapter-specific)_  | —                               | See [Adapter API](/api/adapters)                                                                                                                              |

BrowserAdapter supports `preset` plus `videoBitrate` and `audioBitrate`. NodeAdapter supports all fields below:

| Field          | Type                        | Description                  |
| -------------- | --------------------------- | ---------------------------- |
| `preset`       | `'h264' \| 'hevc' \| 'vp9'` | Shorthand encoding profile   |
| `videoCodec`   | `string`                    | Overrides preset video codec |
| `audioCodec`   | `string`                    | Overrides preset audio codec |
| `format`       | `string`                    | Output container (`-f`)      |
| `crf`          | `number`                    | Quality (x264/x265/vp9)      |
| `videoBitrate` | `string \| number`          | Video bitrate                |
| `audioBitrate` | `string \| number`          | Audio bitrate                |
| `speed`        | `HlsDownloaderEncoderSpeed` | x264/x265 encoder preset     |

#### Example: aborting a download with AbortController

```ts
const controller = new AbortController();

// Abort after 5 seconds (e.g. user clicked cancel)
setTimeout(() => controller.abort(), 5000);

try {
  await downloader.download({
    url: 'https://example.com/stream.m3u8',
    filename: 'output',
    signal: controller.signal,
  });
} catch (err) {
  if (err.name === 'AbortError') {
    console.log('download aborted');
  } else {
    throw err;
  }
}
```

### `downloadToStream()`

External-audio output with initial track offsets is verified for file/Blob playback. Chromium MSE ignores leading empty edits; an MSE host must map timestamps per track instead of appending these multiplexed bytes unchanged to one SourceBuffer. The SDK does not provide that MSE mapping.

<Callout type="info" title="BrowserAdapter & NodeAdapter">
  `downloadToStream()` is supported on both **`BrowserAdapter`** and **`NodeAdapter`**, and both
  emit fragmented MP4 incrementally. Use writable output for asynchronous consumer backpressure.
</Callout>

```ts
async downloadToStream(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions,
  onChunk: (bytes: Uint8Array) => void,
): Promise<HlsDownloaderStreamResult>
```

Parses HLS, transmuxes, and pushes fMP4 bytes through `onChunk`. **The library itself does not write to disk.**

#### Incremental output

Both adapters download and emit fMP4 incrementally. `onChunk` is synchronous: the library waits for callback execution, but not a returned Promise or a downstream Node stream’s `drain`. Use `downloadToWritable()` when the destination performs asynchronous writes.

Output starts with `ftyp` and `moov`, followed by fMP4 fragments. Media buffering is bounded for stream/writable paths; full playlist metadata and the caller’s own buffering are separate.

Merges per-call options with `globalOptions` (per-call wins).

| Option                | Type                     | Description                                                                                                                                                                                    |
| --------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`                 | `string`                 | HLS playlist URL                                                                                                                                                                               |
| `headers`             | `Record<string, string>` | Request headers                                                                                                                                                                                |
| `filename`            | `string`                 | Ignored on streaming path (no file is written); accepted for option compatibility                                                                                                              |
| `maxRetry`            | `number`                 | Total attempts including the first request; effective on Browser and Node streaming paths                                                                                                      |
| `operationId`         | `string`                 | Optional caller-defined event correlation ID; generated automatically when omitted                                                                                                             |
| `downloadConcurrency` | `number`                 | Concurrent segment downloads                                                                                                                                                                   |
| `signal`              | `AbortSignal`            | Cooperative cancellation. When the signal aborts, the stream rejects with an `AbortError`. On `BrowserAdapter`, abort during the prefetch phase is limited to `fetch`-level signal propagation |
| `variant`             | `VariantSelectOptions`   | Master-playlist variant selection preferences. Omit for default (highest resolution → bandwidth)                                                                                               |

Returns `{ totalSegments: number, operationId: string }`.

#### Example: HTTP server streaming to a browser (stream + persist)

```ts
import { createServer } from 'node:http';
import { writeFile } from 'node:fs/promises';
import { HlsDownloader } from '@hls-downloader/core';
import { NodeAdapter } from '@hls-downloader/adapters/node';

const downloader = new HlsDownloader({ adapter: NodeAdapter });

const server = createServer(async (req, res) => {
  if (req.url !== '/stream.mp4') {
    res.writeHead(404);
    return res.end('not found');
  }

  res.writeHead(200, {
    'Content-Type': 'video/mp4', // fMP4 — browser MSE can parse
    'Cache-Control': 'no-cache',
    // No Content-Length — streaming, length unknown
  });

  // The library does not write to disk: bytes from onChunk go to both
  // the HTTP response and a buffer for later file write.
  const fileChunks: Uint8Array[] = [];
  await downloader.downloadToStream(
    {
      url: 'https://example.com/stream.m3u8',
      headers: { Authorization: 'Bearer ...' },
      downloadConcurrency: 8,
    },
    (bytes) => {
      res.write(bytes); // stream as-you-go
      fileChunks.push(bytes); // buffer for later file write
    },
  );
  res.end();

  // Write the file afterwards (or use ReadableStream.tee() to persist in parallel during the stream)
  await writeFile('output.mp4', Buffer.concat(fileChunks.map((c) => Buffer.from(c))));
});

server.listen(3000);
```

<Callout type="info" title="Recommended approach for stream + persist in parallel">
If you want to persist the file in parallel during the stream (rather than after), wrap `onChunk` into a `ReadableStream`, then fork with `stream.tee()`:
- branch 1 → HTTP response (live playback)
- branch 2 → `Bun.write(filePath, branch)` or `pipeline(branch, createWriteStream(filePath))` (background file write)

`tee()` provides backpressure and ordering guarantees; the two branches consume independently. The file becomes available once the task completes.

</Callout>

<Callout type="info" title="Resume not supported">
  The streaming path writes to a non-seekable sink, so `resume` is not supported. If the stream
  fails midway, restart from the beginning.
</Callout>

### `getPosterUrl()`


Attempt to extract a poster/thumbnail image URL from the stream. Merges `options` with `globalOptions.download` (headers only). Returns the URL string if found, otherwise `undefined`.

```ts

```

## Variant selection

When `parseHls()` returns a master playlist, `download()` / `downloadToStream()` pick one variant via `selectBestVariant`. The default strategy:

1. Exclude audio-only variants (unless `includeAudioOnly`).
2. Exclude variants exceeding `maxResolution` / `maxBandwidth` (if set); fall back to the unfiltered list if all are excluded.
3. Score by `preferredCodec` → `preferredAudio` → resolution (pixels) → bandwidth, picking the highest.

Steer selection per-call with the `variant` option:

```ts
await downloader.download({
  url: 'https://example.com/master.m3u8',
  variant: {
    maxResolution: { width: 1280, height: 720 },
    preferredCodec: 'hvc1',
  },
});
```

See [VariantSelectOptions](/api/types#variantselectoptions) for the full option shape. `selectBestVariant` and the `VariantSelector` type are exported from `@hls-downloader/shared` for custom strategies.

### `downloadToWritable()`

```ts
async downloadToWritable(
  options: HlsDownloaderWritableOptions,
  writable: WritableStream<Uint8Array>,
): Promise<HlsDownloaderStreamResult>
```

Browser and Node support incremental fMP4 output with backpressure. Source codecs are preserved; per-call `transcode` is rejected and global transcode settings are ignored. Check `downloader.capabilities.writableOutput === true`; Adapters without this optional capability reject with `UNSUPPORTED_OUTPUT` before acquiring the writer.

The library owns the acquired writer: it awaits each write and closes it on success. `READY_FOR_DOWNLOAD` and promise resolution occur only after close succeeds. Failure/cancellation aborts the writer and releases its lock. Writer acquisition, write and close errors use `OUTPUT_WRITE_FAILED`; cancellation uses `ABORTED` with `name === 'AbortError'`. Each failed operation emits one `ERROR`. A custom sink may retain partial output; arbitrary external writes cannot be rolled back. An uncooperative pending write does not prevent the promise returned by the library from rejecting on cancellation; its eventual abort is observed asynchronously.

`downloadConcurrency` limits aggregate reads. Dual-input sessions retain the current segment and one lookahead per input, plus initialization probes, the current output fragment, and bridge buffers. Media buffers do not grow with total video length. Playlist metadata still grows with segment count, a large individual segment may require substantial memory, and WASM memory retains its allocation high-water mark. This is not a fixed RSS limit. The fMP4 output omits the trailing `mfra` index.

`download()` produces a complete Browser Blob URL or a Node file; callback streaming is incremental but does not await callback promises. `persistentOutput` describes the default `download()` result and remains false for Browser; `writableOutput` describes this separate caller-owned destination.

#### Save directly to a file

The caller opens the picker during user activation and passes its writable stream. File System Access availability and permissions are application concerns; the library never opens a picker or silently falls back to buffering a Blob. The example assumes `#save` and `#cancel` buttons and a browser with `showSaveFilePicker`; a cancelled controller is one-shot, so create a new one for another operation.

```js
import { HlsDownloader } from '@hls-downloader/core';
import { BrowserAdapter } from '@hls-downloader/adapters/browser';

const downloader = new HlsDownloader({ adapter: BrowserAdapter });
const controller = new AbortController();
// Invoke directly from a user click; do not await library initialization first.
document.querySelector('#save').addEventListener('click', async () => {
  try {
    const handle = await window.showSaveFilePicker({
      suggestedName: 'video.mp4',
      types: [{ description: 'MP4 video', accept: { 'video/mp4': ['.mp4'] } }],
    });
    const writable = await handle.createWritable();
    await downloader.downloadToWritable(
      { url: 'https://example.com/video.m3u8', signal: controller.signal },
      writable,
    );
  } catch (error) {
    console.error('Download or saving failed', error);
  }
});
document.querySelector('#cancel').addEventListener('click', () => controller.abort());
```

### Node resumable downloads (v3.6)

```ts
import { HlsDownloader } from '@logosw/hls-downloader/core';
import { NodeAdapter, type NodeAdapterResumeOptions } from '@logosw/hls-downloader/adapters/node';

const downloader = new HlsDownloader({ adapter: NodeAdapter });
const resume: NodeAdapterResumeOptions = { directory: './download-jobs/video' };
const result = await downloader.download({
  url: 'https://example.com/media.m3u8',
  filename: 'video',
  resume,
  signal: new AbortController().signal,
});
// After interruption, call download again with the same options and a new signal.
```

`resume` is available only on a single Node `download()` call. Relative directories and output filenames are resolved against the working directory at call time. Use an empty, dedicated directory for each task. Only plain VOD TS/fMP4 downloads, including BYTERANGE and MAP, are supported. Per-call or global transcoding and enabled aria2 are rejected with `UNSUPPORTED_OUTPUT`; Browser, callback streaming and writable output do not support recovery.

Retry with the same original URL (including signed query parameters), effective headers, variant selection and output target. A new `operationId`, signal, retry count or concurrency is allowed. Download recovery fetches the playlist again and requires unchanged content and resolved location; input changes return `RESUME_INVALID` and preserve the directory. Start with a new directory to change inputs. Finalizing and completed tasks recover locally without fetching manifests.

Verified cached resources avoid repeated media requests; corrupted cache entries are fetched again. Cache hashes detect local corruption, not remote changes at a stable URL. A resumable download still assumes immutable VOD content. Segment progress includes already committed segments. Output is published before `READY_FOR_DOWNLOAD` and promise resolution.

On failure or cancellation, the directory retains valid recovery data and releases its lock. On success, media caches and partial output are removed, while the lock file and a small completion receipt remain. Repeating a completed call validates and returns the existing output without downloading again. Cleanup failure does not invalidate a delivered output. `clearCache()` does not remove recovery data; delete the dedicated directory when abandoning or forgetting the task. Filesystem durability remains subject to the operating system and filesystem guarantees.

| Error              | Meaning                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------- |
| `RESUME_CONFLICT`  | Another process or operation holds the directory lock.                                        |
| `RESUME_INVALID`   | Invalid directory, changed identity, invalid checkpoint, or missing/changed completed output. |
| `RESUME_IO_FAILED` | Recovery storage, checkpoint persistence, or output publication failed.                       |
| `ABORTED`          | Cancelled; the error retains `name === 'AbortError'`.                                         |

## Browser request options

All six media methods accept `browserRequest` for BrowserAdapter. Per-call configuration replaces instance `options.browserRequest`; `{}` restores native defaults. Browser operations do not share playlist/poster results across calls. See [Adapter API](/api/adapters#browser-media-request-context).

### Audio renditions and WebVTT

```ts
const source = { url: 'https://example.test/master.m3u8' };
const parsed = await downloader.parseHls(source);
if (parsed.type === 'playlist') console.log(parsed.renditions);

await downloader.downloadToWritable(
  { ...source, audio: { language: 'en' } },
  destination, // WHATWG WritableStream<Uint8Array>
);
const subtitles = await downloader.downloadSubtitles({
  ...source,
  audio: { language: 'en' },
  subtitle: { groupId: 'subs', name: 'English' },
});
console.log(subtitles.text); // save as subtitles.filename
```

Audio selection applies after variant selection and only within its referenced audio group. With no explicit selection, DEFAULT wins, then AUTOSELECT, then declaration order. External audio replaces embedded audio; a URI-less rendition keeps embedded audio. Output contains one selected audio track. Unsupported alternate video groups fail explicitly.

Alternate audio supports clear, AES-128 and the sample encryption profiles listed in the adapter API for finite VOD TS/fMP4. It cannot be combined with resume, transcoding, or aria2. Unselected subtitles are never fetched. Without `timeline`, prepared inputs must share a reliable presentation clock; timestamp resets and unrepresentable gaps fail. Explicit `timeline` enables the epoch and gap policies below.

`downloadSubtitles()` is a separate operation exporting one external WebVTT rendition. It probes the selected media’s initialization/first segments to obtain the same output timeline, then fetches subtitle segments. It supports MAP, timestamp mapping/wrap, empty segments, cue deduplication, and cue settings. Cues before output zero are omitted or clipped at zero. Malformed subtitles fail with `SUBTITLE_INVALID`; no subtitles are embedded in MP4 and no SRT conversion is performed.

Node writable accepts WHATWG streams. To use a Node writable, pass `Writable.toWeb(nodeWritable)` from `node:stream`; the downloader owns close/abort for the operation.

### `parseMediaPlaylist(text, url)`

```ts
const playlist = await downloader.parseMediaPlaylist(text, finalPlaylistUrl);
const sequence = BigInt(playlist.segments[0].originalSequence);
```

Parses an already-selected media playlist from its raw text and final URL. Returns versioned `HlsMediaPlaylist` metadata, preserving decimal-string sequences/ranges/ticks, KEY candidates, MAP declaration context, NONE transitions, gaps and discontinuities. It does not select a master rendition or request keys/media. Browser may load WASM for this parser; the lightweight `parseHls()` behavior is unchanged. Parsing alone does not guarantee executable media support.

## Timeline ranges and multiple outputs

`timeline` explicitly enables the finite timeline path on `download()`, `downloadToStream()` and `downloadToWritable()`. Omit it to retain the existing route and startup behavior. Times use exact `{ ticks: string, timescale: number }` values. Ranges are half-open presentation intervals; video expands to verified independent access points and retains necessary preroll/tail GOPs. An end beyond EOF clips; empty, wholly out-of-bounds or undecodable ranges fail with `RANGE_INVALID`.

```ts
const result = await downloader.download({
  url: 'https://example.com/media.m3u8',
  timeline: {
    range: { start: { ticks: '5', timescale: 1 }, end: { ticks: '12', timescale: 1 } },
    gapPolicy: 'preserve',
  },
});
console.log(result.timelineReport?.actual);
```

`timelineReport` adds requested/actual intervals, optional preroll/postroll intervals, ordered per-output track/epoch mappings, dependencies and read/planning counters. `schemaVersion: 1` is diagnostic JSON, not a checkpoint. `totalSegments` counts output media resources and can count a resource in more than one split output. All protocol-sized counters and indexes remain decimal strings.

Default `gapPolicy: 'preserve'` keeps representable gaps. `'collapse'` removes only gaps common to the selected tracks. Single outputs fail on configuration changes or gaps they cannot express. `epochAnchors: [{ inputId, epoch, source, presentation }]` supplies explicit reset evidence; inputs are `primary` and optional `audio`. Ambiguous clocks fail rather than synchronizing by rendition sequence. `tailDuration` is an explicit positive media-time fallback when the source provides insufficient tail evidence.

`timeline.limits` defaults to 65,536 sample records and 4,096 cursor resources. Resource/key limits remain under `decryption.limits`, including for clear timeline operations. Scan and validation finish before first output, so startup includes finite scanning and may reread resources; changed bytes or decrypted packets fail with `RESOURCE_CHANGED`. These limits do not bound total RSS: finite catalogs, reports and classic MP4 buffers/indexes have separate costs.

### `downloadOutputs(options)`

This independent API returns `{ operationId, totalSegments, outputs, timelineReport }`. Each output has a decimal-string `index` plus `blobURL` (Browser) or `filePath` (Node). Outputs are classic MP4. Node uses `basename.001.mp4`, `basename.002.mp4`, etc. Browser creates Blob URLs only after every output succeeds; callers must revoke them after use.

Pass `timeline: { changePolicy: 'split' }` to split at decodable configuration changes or otherwise unrepresentable gaps. The default is `'fail'`. A representable fMP4 gap does not itself require splitting. Existing single-output APIs never accept this policy.

### `downloadToWritables(options, outputFactory)`

```ts
const result = await downloader.downloadToWritables(
  { url, timeline: { changePolicy: 'split' } },
  async ({ index, actualRange, reason, tracks }) => {
    return await createDestination(index); // Promise<WritableStream<Uint8Array>>
  },
);
```

The factory runs after finite validation and returns a distinct fMP4 destination. The next destination is acquired before the old output completes. Writes await backpressure; public completion waits for destination close. A failed next acquisition does not complete the current output. Cancellation aborts acquired, unfinished writers; late factory results are aborted. Failures expose `completedOutputs` containing only published files or successfully closed writable outputs. Their media remains usable; partial writers are not recovery checkpoints.

Timeline operations reject resume, transcoding and aria2. Writable APIs continue ignoring global transcode defaults and reject per-call transcoding. Existing clear single-input recovery remains available outside timeline. Callback streaming still does not await callback promises. Multiplexed fMP4 is not a guarantee of direct MSE compatibility; hosts still need track-aware timestamp mapping where required.

## Timeline subtitle and chapter sidecars

`downloadSubtitleOutputs({ url, subtitle, timelineReport, track?, filename? })` exports finite **clear** WebVTT on a completed report from the same source/track selection. It returns `{ operationId, totalSegments, outputs }`; each sidecar contains `outputIndex`, `text`, `filename` and `mimeType: 'text/vtt'`. It fetches manifests and subtitle resources without decoding the primary media again. X-TIMESTAMP-MAP and available PDT evidence resolve source clocks; ambiguous resets fail with `SUBTITLE_INVALID`.

`exportChapters({ chapters, timelineReport, track?, filename? })` is a synchronous named export from the root/shared package. Each chapter has `{ range: { start, end }, title, id? }` on the public presentation timeline. It returns one WebVTT chapters sidecar per output. Both operations default to the primary video track, or primary audio for audio-only output; `track: { inputId, trackId }` selects a report mapping explicitly. Intervals are clipped and split at mapped boundaries, rebased to output time, then serialized to millisecond WebVTT timestamps. Neither operation writes sidecar files automatically.

Existing `downloadSubtitles()` is unchanged. Encrypted subtitle resources and subtitle embedding remain unsupported.
