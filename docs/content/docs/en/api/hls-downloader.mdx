---

The main facade class for downloading HLS streams. Imported from `@hls-downloader/core`.

<Callout type="info" title="Default download path (transmux)">
**Ordinary `download()` keeps source codecs and transmuxes to MP4.** BrowserAdapter uses [hls-engine](https://github.com/Logosww/hls-engine) WebAssembly; NodeAdapter uses its native Rust path.

Re-encoding is opt-in via `transcode` — see [Adapter API](/api/adapters). BrowserAdapter loads its hls-engine WASM module in `init()`; NodeAdapter is a no-op (FFmpeg loads on demand). `parseHls()` never starts those engines.

</Callout>

## Constructor

```ts
new HlsDownloader({
  adapter,
  options?,
  onEvent?,
})
```

| Parameter | Type                            | Description                                                                                 |
| --------- | ------------------------------- | ------------------------------------------------------------------------------------------- |
| `adapter` | `BrowserAdapter \| NodeAdapter` | The adapter to use                                                                          |
| `options` | `GlobalOptions<T>`              | Default options (see below). Merged into each `parseHls` / `download` / `getPosterUrl` call |
| `onEvent` | `(event, payload?) => void`     | Event callback for tracking progress and errors                                             |

## Properties

### `isInit`

```ts
get isInit(): boolean
```

Whether the adapter has been initialized. Returns `true` after `init()` resolves.

### `globalOptions`

```ts
get globalOptions(): GlobalOptions<T> | null
```

The current default options, or `null` if none were set.

## GlobalOptions

Exported from `@hls-downloader/core` as `GlobalOptions<T>`. The shape depends on the adapter type `T`.

| Field                | Type                                 | Description                                                  |
| -------------------- | ------------------------------------ | ------------------------------------------------------------ |
| `download`           | `HlsDownloaderGlobalDownloadOptions` | Default fetch / download settings (excluding per-call `url`) |
| `transcode`          | `HlsDownloaderTranscodeOptions`      | Default transcode settings                                   |
| _(adapter-specific)_ | —                                    | See [Adapter API](/api/adapters)                             |

### `download` object

| Field         | Type                     | Description                            |
| ------------- | ------------------------ | -------------------------------------- |
| `headers`     | `Record<string, string>` | Default request headers                |
| `concurrency` | `number`                 | Default concurrent segment downloads   |
| `maxRetry`    | `number`                 | Default max retry attempts per segment |

Per-call `download({ downloadConcurrency })` overrides `download.concurrency`.

## Methods

### `init()`

```ts
async init(): Promise<void>
```

Initialize adapter state. BrowserAdapter loads its WASM module (transmux engine) here — this is the main startup cost on the browser, so callers may want to invoke `init()` ahead of time (e.g. on page load) rather than letting it block the first `download()` / `downloadToStream()`. NodeAdapter is a no-op (FFmpeg loads on demand). The call is idempotent — repeated invocations share the same promise.

`download()` and `downloadToStream()` automatically call `init()` if not yet initialized. `parseHls()` and `getPosterUrl()` do **not** trigger `init()` and work without initialization.

### `setOptions()`

```ts
setOptions(options: GlobalOptions<T>): void
```

Replace the default options. Accepts the same shape as the constructor `options`.

### `parseHls()`

```ts
async parseHls(options: HlsDownloaderFetchOptions): Promise<ParseHlsResult>
```

Parse an HLS playlist without downloading segments. Merges `options` with `globalOptions.download` (headers only).

Returns a `ParseHlsResult`:

- `{ type: 'playlist', data: Playlist[] }` — master playlist with variant streams
- `{ type: 'segment', data: Segment[] }` — media playlist with segments
- `{ type: 'error', message: string }` — parse error

| Option    | Type                     | Description      |
| --------- | ------------------------ | ---------------- |
| `url`     | `string`                 | HLS playlist URL |
| `headers` | `Record<string, string>` | Request headers  |

### `download()`

```ts
async download(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions & Partial<AdapterOptions>
): Promise<DownloadResult>
```

Parse, download all segments, and merge them into a single file. On success, **`BrowserAdapter`** resolves to `{ blobURL, totalSegments }`; **`NodeAdapter`** resolves to `{ filePath, totalSegments }`. On failure, the promise rejects.

**By default (no `transcode`)**, adapters use the transmux path and keep source codecs. Passing `transcode` opts into re-encoding: BrowserAdapter uses WebCodecs; NodeAdapter uses FFmpeg.

Merges per-call options with `globalOptions` (per-call wins).

| Option                | Type                            | Description                                                                                                                                                   |
| --------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`                 | `string`                        | HLS playlist URL                                                                                                                                              |
| `headers`             | `Record<string, string>`        | Request headers                                                                                                                                               |
| `filename`            | `string`                        | Output filename without extension. The extension is resolved internally from the output container (`mp4` by default, `webm` for `vp9`, or `transcode.format`) |
| `maxRetry`            | `number`                        | Max retry attempts per segment                                                                                                                                |
| `downloadConcurrency` | `number`                        | Concurrent segment downloads                                                                                                                                  |
| `transcode`           | `HlsDownloaderTranscodeOptions` | Transcode with WebCodecs in BrowserAdapter or FFmpeg in NodeAdapter. Omit for default transmux/remux                                                          |
| `signal`              | `AbortSignal`                   | Cooperative cancellation. When the signal aborts, the download promise rejects with an `AbortError`                                                           |
| `variant`             | `VariantSelectOptions`          | Master-playlist variant selection preferences. Omit for default (highest resolution → bandwidth)                                                              |
| _(adapter-specific)_  | —                               | See [Adapter API](/api/adapters)                                                                                                                              |

BrowserAdapter supports `preset` plus `videoBitrate` and `audioBitrate`. NodeAdapter supports all fields below:

| Field          | Type                        | Description                  |
| -------------- | --------------------------- | ---------------------------- |
| `preset`       | `'h264' \| 'hevc' \| 'vp9'` | Shorthand encoding profile   |
| `videoCodec`   | `string`                    | Overrides preset video codec |
| `audioCodec`   | `string`                    | Overrides preset audio codec |
| `format`       | `string`                    | Output container (`-f`)      |
| `crf`          | `number`                    | Quality (x264/x265/vp9)      |
| `videoBitrate` | `string \| number`          | Video bitrate                |
| `audioBitrate` | `string \| number`          | Audio bitrate                |
| `speed`        | `HlsDownloaderEncoderSpeed` | x264/x265 encoder preset     |

#### Example: aborting a download with AbortController

```ts
const controller = new AbortController();

// Abort after 5 seconds (e.g. user clicked cancel)
setTimeout(() => controller.abort(), 5000);

try {
  await downloader.download({
    url: 'https://example.com/stream.m3u8',
    filename: 'output',
    signal: controller.signal,
  });
} catch (err) {
  if (err.name === 'AbortError') {
    console.log('download aborted');
  } else {
    throw err;
  }
}
```

### `downloadToStream()`

External-audio output with initial track offsets is verified for file/Blob playback. Chromium MSE ignores leading empty edits; an MSE host must map timestamps per track instead of appending these multiplexed bytes unchanged to one SourceBuffer. The library does not provide that MSE mapping.

<Callout type="info" title="BrowserAdapter & NodeAdapter">
  `downloadToStream()` is supported on both **`BrowserAdapter`** and **`NodeAdapter`**, and both
  emit fragmented MP4 incrementally. Use writable output for asynchronous consumer backpressure.
</Callout>

```ts
async downloadToStream(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions,
  onChunk: (bytes: Uint8Array) => void,
): Promise<HlsDownloaderStreamResult>
```

Parses HLS, transmuxes, and pushes fMP4 bytes through `onChunk`. **The library itself does not write to disk.**

#### Incremental output

Both adapters download and emit fMP4 incrementally. `onChunk` is synchronous: the library waits for callback execution, but not a returned Promise or a downstream Node stream’s `drain`. Use `downloadToWritable()` when the destination performs asynchronous writes.

Output starts with `ftyp` and `moov`, followed by fMP4 fragments. Media buffering is bounded for stream/writable paths; full playlist metadata and the caller’s own buffering are separate.

Merges per-call options with `globalOptions` (per-call wins).

| Option                | Type                     | Description                                                                                                                                                                                    |
| --------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `url`                 | `string`                 | HLS playlist URL                                                                                                                                                                               |
| `headers`             | `Record<string, string>` | Request headers                                                                                                                                                                                |
| `filename`            | `string`                 | Ignored on streaming path (no file is written); accepted for option compatibility                                                                                                              |
| `maxRetry`            | `number`                 | Total attempts including the first request; effective on Browser and Node streaming paths                                                                                                      |
| `operationId`         | `string`                 | Optional caller-defined event correlation ID; generated automatically when omitted                                                                                                             |
| `downloadConcurrency` | `number`                 | Concurrent segment downloads                                                                                                                                                                   |
| `signal`              | `AbortSignal`            | Cooperative cancellation. When the signal aborts, the stream rejects with an `AbortError`. On `BrowserAdapter`, abort during the prefetch phase is limited to `fetch`-level signal propagation |
| `variant`             | `VariantSelectOptions`   | Master-playlist variant selection preferences. Omit for default (highest resolution → bandwidth)                                                                                               |

Returns `{ totalSegments: number, operationId: string }`.

#### Example: HTTP server streaming to a browser (stream + persist)

```ts
import { createServer } from 'node:http';
import { writeFile } from 'node:fs/promises';
import { HlsDownloader } from '@hls-downloader/core';
import { NodeAdapter } from '@hls-downloader/adapters/node';

const downloader = new HlsDownloader({ adapter: NodeAdapter });

const server = createServer(async (req, res) => {
  if (req.url !== '/stream.mp4') {
    res.writeHead(404);
    return res.end('not found');
  }

  res.writeHead(200, {
    'Content-Type': 'video/mp4', // fMP4 — browser MSE can parse
    'Cache-Control': 'no-cache',
    // No Content-Length — streaming, length unknown
  });

  // The library does not write to disk: bytes from onChunk go to both
  // the HTTP response and a buffer for later file write.
  const fileChunks: Uint8Array[] = [];
  await downloader.downloadToStream(
    {
      url: 'https://example.com/stream.m3u8',
      headers: { Authorization: 'Bearer ...' },
      downloadConcurrency: 8,
    },
    (bytes) => {
      res.write(bytes); // stream as-you-go
      fileChunks.push(bytes); // buffer for later file write
    },
  );
  res.end();

  // Write the file afterwards (or use ReadableStream.tee() to persist in parallel during the stream)
  await writeFile('output.mp4', Buffer.concat(fileChunks.map((c) => Buffer.from(c))));
});

server.listen(3000);
```

<Callout type="info" title="Recommended approach for stream + persist in parallel">
If you want to persist the file in parallel during the stream (rather than after), wrap `onChunk` into a `ReadableStream`, then fork with `stream.tee()`:
- branch 1 → HTTP response (live playback)
- branch 2 → `Bun.write(filePath, branch)` or `pipeline(branch, createWriteStream(filePath))` (background file write)

`tee()` provides backpressure and ordering guarantees; the two branches consume independently. The file becomes available once the task completes.

</Callout>

<Callout type="info" title="Resume not supported">
  The streaming path writes to a non-seekable sink, so `resume` is not supported. If the stream
  fails midway, restart from the beginning.
</Callout>

## Variant selection

When `parseHls()` returns a master playlist, `download()` / `downloadToStream()` pick one variant via `selectBestVariant`. The default strategy:

1. Exclude audio-only variants (unless `includeAudioOnly`).
2. Exclude variants exceeding `maxResolution` / `maxBandwidth` (if set); fall back to the unfiltered list if all are excluded.
3. Score by `preferredCodec` → `preferredAudio` → resolution (pixels) → bandwidth, picking the highest.

Steer selection per-call with the `variant` option:

```ts
await downloader.download({
  url: 'https://example.com/master.m3u8',
  variant: {
    maxResolution: { width: 1280, height: 720 },
    preferredCodec: 'hvc1',
  },
});
```

See [VariantSelectOptions](/api/types#variantselectoptions) for the full option shape. `selectBestVariant` and the `VariantSelector` type are exported from `@hls-downloader/shared` for custom strategies.

### `downloadToWritable()`

```ts
async downloadToWritable(
  options: HlsDownloaderWritableOptions,
  writable: WritableStream<Uint8Array>,
): Promise<HlsDownloaderStreamResult>
```

Browser and Node support incremental fMP4 output with backpressure. Source codecs are preserved; per-call `transcode` is rejected and global transcode settings are ignored. Check `downloader.capabilities.writableOutput === true`; Adapters without this optional capability reject with `UNSUPPORTED_OUTPUT` before acquiring the writer.

The library owns the acquired writer: it awaits each write and closes it on success. `READY_FOR_DOWNLOAD` and promise resolution occur only after close succeeds. Failure/cancellation aborts the writer and releases its lock. Writer acquisition, write and close errors use `OUTPUT_WRITE_FAILED`; cancellation uses `ABORTED` with `name === 'AbortError'`. Each failed operation emits one `ERROR`. A custom sink may retain partial output; arbitrary external writes cannot be rolled back. An uncooperative pending write does not prevent the promise returned by the library from rejecting on cancellation; its eventual abort is observed asynchronously.

`downloadConcurrency` limits aggregate reads. Dual-input sessions retain the current segment and one lookahead per input, plus initialization probes, the current output fragment, and bridge buffers. Media buffers do not grow with total video length. Playlist metadata still grows with segment count, a large individual segment may require substantial memory, and WASM memory retains its allocation high-water mark. This is not a fixed RSS limit. The fMP4 output omits the trailing `mfra` index.

`download()` produces a complete Browser Blob URL or a Node file; callback streaming is incremental but does not await callback promises. `persistentOutput` describes the default `download()` result and remains false for Browser; `writableOutput` describes this separate caller-owned destination.

#### Save directly to a file

The caller opens the picker during user activation and passes its writable stream. File System Access availability and permissions are application concerns; the library never opens a picker or silently falls back to buffering a Blob. The example assumes `#save` and `#cancel` buttons and a browser with `showSaveFilePicker`; a cancelled controller is one-shot, so create a new one for another operation.

```js
import { HlsDownloader } from '@hls-downloader/core';
import { BrowserAdapter } from '@hls-downloader/adapters/browser';

const downloader = new HlsDownloader({ adapter: BrowserAdapter });
const controller = new AbortController();
// Invoke directly from a user click; do not await library initialization first.
document.querySelector('#save').addEventListener('click', async () => {
  try {
    const handle = await window.showSaveFilePicker({
      suggestedName: 'video.mp4',
      types: [{ description: 'MP4 video', accept: { 'video/mp4': ['.mp4'] } }],
    });
    const writable = await handle.createWritable();
    await downloader.downloadToWritable(
      { url: 'https://example.com/video.m3u8', signal: controller.signal },
      writable,
    );
  } catch (error) {
    console.error('Download or saving failed', error);
  }
});
document.querySelector('#cancel').addEventListener('click', () => controller.abort());
```

## Unified Engine output

All HLS download, stream, timeline and recording methods use `hls-engine 1.0`.
Existing method names remain available. FFmpeg and WebCodecs remain the separate
transcoding paths. Finite methods require ENDLIST on every selected input;
`startRecording()` and `startMultiTrackRecording()` also support Live/EVENT refresh.

Results expose `report: HlsEngineReport`. It contains input progress, tracks,
subtitle receipts, completed outputs, requested/actual ranges, bounded mappings
and history truncation flags. Protocol counters, generations, sequences and ticks
are decimal strings; use `BigInt`, not `Number`, when exactness matters. The old
`timelineReport` and full resource/sample index contract have been removed.

`download()` selects the default external audio rendition unless `audio` selects
another. `downloadMultiTrack()` requires `embeddedAudio: 'keep' | 'exclude'` and
accepts `audioTracks`, `subtitleTracks` and `playbackTarget`. Unselected renditions
are not fetched. `parseMediaPlaylist(text, url)` parses lossless metadata without
fetching media; `parseHls()` continues exposing variant and rendition selection.

Browser `download({ url, maxBytes? })` defaults to a 256 MiB collection limit.
Recording with `{ type: 'blob', maxBytes }` always requires an explicit capacity.
This limits collected bytes, not total process memory or classic MP4 index costs.
`downloadToWritable()` and `downloadToWritables()` await every write and close;
callback `downloadToStream()` does not await callback promises.

`downloadOutputs()` returns `{ operationId, totalSegments, outputs, report }`.
Browser outputs are fMP4 Blob URLs; Node outputs are classic MP4 files named
`basename.001.mp4`, `basename.002.mp4`, etc. Revoke Blob URLs when finished.
`downloadToWritables()` acquires each sink from the supplied factory. Split uses
`timeline.changePolicy: 'split'`; a single borrowed sink cannot split.
Failures retain already published files or successfully closed writable outputs
in `error.completedOutputs`. READY/result completion follows destination close.

## Continuous WebVTT sidecars

`downloadMultiTrack()` and `startMultiTrackRecording()` accept plain-text WebVTT
and AES-128 WebVTT segments/MAPs, including key rotation and original sequence IVs.
Subtitle resources share the operation's key session, cancellation and resource
budgets with media. SAMPLE-AES, CTR and GCM WebVTT remain unsupported. Styling
blocks and rich cue markup are outside the continuous plain-text contract;
standard cue settings are preserved.

```ts
const session = downloader.startMultiTrackRecording({
  url,
  embeddedAudio: 'keep',
  subtitleTracks: [{
    id: 'english',
    selector: { groupId: 'subs', name: 'English' },
    embedded: false,
    sidecar: { type: 'writable', writable: subtitleWritable },
  }],
  output: { type: 'writable', writable: mediaWritable },
  onEvent(event) {
    if (event.type === 'subtitleCommit') console.log(event.commit.frontiers);
  },
});
// Later: session.stop(); await session.result;
```

Both runtimes await sidecar writes and closes. `embedded` defaults to `true`;
`false` requires a sidecar and avoids adding a wvtt track to the container.
For split outputs, use `{ type: 'writables', acquire: async ({ inputId,
outputIndex }) => writable }` on each subtitle selection. Each writer must be
distinct from the media writer and other active subtitle writers. The preceding
output closes before the next is acquired. A borrowed single Writable cannot split.

Each output starts with one UTF-8 `WEBVTT` header. Cues use the actual committed
output clock, including range clipping and split rebasing; long cues may be emitted
as several portions. Timestamps are floored to milliseconds and portions that
become empty are omitted. `subtitleCommit` exposes exact rational times, receipt,
track/input, generation/epoch, output identity, clipping/rejection disposition and
commit frontiers. It is an observation event: callback return values do not provide
backpressure or durable acknowledgement. The sidecar sink does. Stop drains accepted
work; cancel rejects without waiting for an uncooperative sink, and late writes
cannot turn cancellation into success. Write/close failures reject with
`OUTPUT_WRITE_FAILED`; already acknowledged Writable bytes cannot be rolled back.

Node also accepts `sidecar: { type: 'file', path: './english.vtt' }` with a fixed
media file output. With `resume: { directory: './job' }`, every selected subtitle
track must have a fixed file sidecar. Writable/factory sidecars cannot resume.
Existing unrelated files are preserved. The requested path is output zero;
subsequent outputs use `<path>.part-000001.vtt`, alongside the media's corresponding
`.part-000001.mp4` outputs. Publication is per file, not an atomic multi-file rename.

The library checkpoint envelope remains schema 2; joint media/subtitle checkpoints
contain Engine archive schema 3 (media-only archives remain schema 2). Recovery
validates all committed prefixes and fresh subtitle resources before truncating
uncommitted tails. Encrypted recovery requires a key resolver returning stable
`version` values. Changed destinations/configuration reject with `RESUME_CONFLICT`;
corrupt prefixes reject with `RESUME_INVALID`; unavailable or changed replay
resources/key versions can require `RESUME_REPLAY_REQUIRED`. No raw keys are
persisted. A completed task restores offline. Keep its directory and partial files
until completion is durable. Subtitle replay metadata shares the bounded recovery
journal (`limits.queuedMetadataBytes`); exhaustion rejects with
`RESOURCE_LIMIT_EXCEEDED`, so this is not an unbounded recovery history.

`downloadSubtitles()` and `downloadSubtitleOutputs()` also accept `decryption`
and `maxBytes` (default 16 MiB for collected UTF-8 subtitle data). The latter uses
the supplied complete timeline map and reads only subtitle resources. Neither
finite export enables continuous recording by itself. `capabilities.multiTrack`
reports `subtitleResources` and `subtitleSidecars`; the `subtitles` field in a
`queryCapability()` request describes embedded subtitles and retains its player restrictions.

## Recording and recovery

A recording handle exposes `result`, `stop()`, `cancel()`, VOD `pause()` / `resume()`,
`endInput(id)` and `restartInput(id, { generation, url? })`. Stop drains accepted
work; cancellation aborts it. Input EOF and generation controls are independent.
Live/EVENT pause is rejected. `limits` bounds descriptors, metadata, samples and
history; `onEvent` observes Engine state, mappings, gaps, progress and outputs.

Node deterministic file downloads and recordings accept:

```ts
const resume = { directory: './jobs/video', durability: 'sync-all' as const };
const result = await node.download({ url, filename: 'video.mp4', resume });
const recording = node.startRecording({
  url,
  output: { type: 'file', path: './recording.mp4' },
  resume: { directory: './jobs/recording' },
  missingSegments: 'fail',
});
```

`durability` is `flush | sync-all`, defaulting to `sync-all`. Flush does not promise
power-loss durability. Use an exclusive task directory. Schema-1 tasks are rejected
with `RESUME_INVALID` and preserved; there is no migration or automatic reset.
Browser, Blob, borrowed Writable and arbitrary file factories cannot resume.
Transcoding and aria2 cannot be combined with Engine recovery.

Before modifying existing output, recovery validates configuration, input/resource
identity, stable key versions, the committed prefix and completed split files.
`RESUME_CONFLICT` identifies configuration, identity or version conflicts;
`RESUME_INVALID` identifies corruption or an old schema; `RESUME_REPLAY_REQUIRED`
identifies missing replay evidence. Inspect `reason` for the specific failure.
Finalizing/completed tasks restore without fetching manifests or replaying media.
Recovery split names use the requested path first, then
`<path>.part-000001.mp4`, `<path>.part-000002.mp4`, etc.

Encrypted recovery requires `decryption.keyResolver` to return a stable `version`.
No raw key bytes are persisted. Renew transport credentials through headers or the
provider without changing media/key resource identities. Keep the task directory
and referenced partials until completion is persisted. Replay storage is bounded
by `limits.queuedMetadataBytes`; exceeding it fails explicitly. For recording
window eviction, choose `missingSegments: 'skip' | 'split'` explicitly or retain
the default `fail`. A resource rewrite is not window eviction.

## Encryption and capability queries

TS, fMP4 and Packed AAC-LC share the Engine pipeline. Supported combinations include
resource AES-128, TS AVC/AAC SAMPLE-AES, Packed AAC SAMPLE-AES, and fMP4 AVC/HEVC/AAC
cenc/cbcs. TS HEVC SAMPLE-AES, Packed AAC CTR, SAMPLE-AES/CTR/GCM WebVTT, LL-HLS partial
segments and arbitrary encrypted byte slices remain unsupported.

`decryption.experimentalGcm: true` opts into the upstream experimental draft-22
`AES-256-GCM` whole-resource profile: a 32-byte key, a 16-byte leading IV and a
16-byte trailing authentication tag. It is disabled by default. No resource
plaintext or samples are committed until authentication succeeds. Invalid key
lengths use `KEY_INVALID`; authentication failures use `AUTHENTICATION_FAILED`.
The key request method union includes `AES-256-GCM`. Do not substitute an AES-128
key, another GCM layout, explicit IV tags or arbitrary byte ranges.

```ts
const decision = await downloader.queryCapability({
  inputs: [
    {
      id: 'primary',
      container: 'fmp4',
      encryption: 'SAMPLE-AES-CTR',
      codecs: ['avc', 'aac-lc'],
      scheme: 'cenc',
    },
  ],
  output: 'writable',
  playbackTarget: 'direct-browser',
});
console.log(decision.containerSupported, decision.playbackSupported);
console.log(decision.rejections, decision.requirements);
```

Queries use declared container, codecs, encryption, output, playback target and
recovery conditions; they do not fetch media or replace runtime validation.
`output` accepts `blob`, `writable`, `file-mp4` and `file-fmp4`. Additional fields
include `mode`, `range`, `embeddedAudio`, `subtitles`, `decodeGaps`, `maxBytes`,
`resume` and `experimentalGcm`. A supported container does not guarantee playback
in a particular browser/player. Errors preserve resource/sample context (input,
generation, epoch, track and sample where available), without key or credential data.

## Timeline maps and sidecars

`report.timelineMap` is a schema-2 `HlsTimelineMap` with explicit intervals per
output/track and a `complete` flag. It is derived from retained Engine mappings,
gaps and completed outputs. `historyEntries` limits history; truncation, missing
boundaries or ambiguity marks the map incomplete. No full media index is promised.

```ts
const { report } = await downloader.downloadToWritable({ url }, writable);
const timelineMap = report!.timelineMap!;
const chapters = exportChapters({
  timelineMap,
  chapters: [
    {
      title: 'Opening',
      range: {
        start: { ticks: '0', timescale: 1 },
        end: { ticks: '5', timescale: 1 },
      },
    },
  ],
});
const subtitles = await downloader.downloadSubtitleOutputs({
  url,
  subtitle: { groupId: 'subs', name: 'English' },
  timelineMap,
});
```

Both exports reject incomplete maps with `SUBTITLE_INVALID`. They clip/split at
known range, gap and output boundaries and convert to the output clock. Use
`track: { inputId, trackId }` to choose a mapping explicitly. Subtitle sidecar
export reads subtitle resources, not the primary media again. Neither helper
writes files automatically. `downloadSubtitles()` remains available and obtains
its media clock through Engine processing.
