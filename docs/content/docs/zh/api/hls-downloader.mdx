用于下载 HLS 流的主门面类。从 `@hls-downloader/core` 导入。

<Callout type="info" title="默认下载路径（Transmux）">
**普通 `download()` 会保留源编码并 transmux 为 MP4。** BrowserAdapter 使用 [hls-transmux](https://github.com/Logosww/hls-transmux) WebAssembly；NodeAdapter 使用原生 Rust 路径。

重编码通过 `transcode` 显式启用 — 见[适配器 API](/zh/api/adapters)。BrowserAdapter 使用 Mediabunny 与 WebCodecs；NodeAdapter 按需加载原生 FFmpeg。`init()` 与 `parseHls()` 均不会启动这些引擎。

</Callout>

## 构造函数

```ts
new HlsDownloader({
  adapter,
  options?,
  onEvent?,
})
```

| 参数      | 类型                            | 描述                                                                       |
| --------- | ------------------------------- | -------------------------------------------------------------------------- |
| `adapter` | `BrowserAdapter \| NodeAdapter` | 使用的适配器                                                               |
| `options` | `GlobalOptions<T>`              | 默认选项（见下文），会与每次 `parseHls` / `download` / `getPosterUrl` 合并 |
| `onEvent` | `(event, payload?) => void`     | 事件回调，用于追踪进度和错误                                               |

## 属性

### `isInit`

```ts
get isInit(): boolean
```

适配器是否已完成初始化。`init()` 成功后为 `true`。

### `globalOptions`

```ts
get globalOptions(): GlobalOptions<T> | null
```

当前默认选项；未设置时为 `null`。

## GlobalOptions

从 `@hls-downloader/core` 导出为 `GlobalOptions<T>`，具体字段随适配器类型 `T` 变化。

| 字段             | 类型                                 | 描述                                      |
| ---------------- | ------------------------------------ | ----------------------------------------- |
| `download`       | `HlsDownloaderGlobalDownloadOptions` | 默认请求 / 下载相关选项（不含单次 `url`） |
| `transcode`      | `HlsDownloaderTranscodeOptions`      | 默认转码选项                              |
| _（适配器专有）_ | —                                    | 见[适配器 API](/zh/api/adapters)          |

### `download` 对象

| 字段          | 类型                     | 描述                     |
| ------------- | ------------------------ | ------------------------ |
| `headers`     | `Record<string, string>` | 默认请求头               |
| `concurrency` | `number`                 | 默认分片并发下载数       |
| `maxRetry`    | `number`                 | 默认每个分片最大重试次数 |

单次调用 `download({ downloadConcurrency })` 会覆盖 `download.concurrency`。

## 方法

### `init()`

```ts
async init(): Promise<void>
```

初始化轻量适配器状态。BrowserAdapter 与 NodeAdapter 仅在后续 API 需要时才启动其重量级引擎。`download()` 会在未初始化时自动触发 `init()`。

### `setOptions()`

```ts
setOptions(options: GlobalOptions<T>): void
```

更新默认选项，结构与构造函数 `options` 相同。

### `parseHls()`

```ts
async parseHls(options: HlsDownloaderFetchOptions): Promise<ParseHlsResult>
```

仅解析 HLS 播放列表，不下载分片。会将 `options` 与 `globalOptions.download` 合并（仅 `headers`）。

返回 `ParseHlsResult`：

- `{ type: 'playlist', data: Playlist[] }` — 主列表及变体流
- `{ type: 'segment', data: Segment[] }` — 媒体列表及分片
- `{ type: 'error', message: string }` — 解析错误

| 选项      | 类型                     | 描述             |
| --------- | ------------------------ | ---------------- |
| `url`     | `string`                 | HLS 播放列表地址 |
| `headers` | `Record<string, string>` | 请求头           |

### `download()`

```ts
async download(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions & Partial<AdapterOptions>
): Promise<DownloadResult>
```

解析、下载全部分片并合并为单个文件。成功时：**`BrowserAdapter`** 解析为 `{ blobURL, totalSegments }`；**`NodeAdapter`** 解析为 `{ filePath, totalSegments }`。失败时 Promise 被拒绝。

**默认（不传 `transcode`）** 各适配器走 transmux 路径并保留源编码。传入 `transcode` 后进入重编码：BrowserAdapter 使用 WebCodecs；NodeAdapter 使用 FFmpeg。

单次传入的选项与 `globalOptions` 合并，单次选项优先。

| 选项                  | 类型                            | 描述                                                                                                         |
| --------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `url`                 | `string`                        | HLS 播放列表地址                                                                                             |
| `headers`             | `Record<string, string>`        | 请求头                                                                                                       |
| `filename`            | `string`                        | 不含扩展名的输出文件名。扩展名由内部根据输出容器解析（默认 `mp4`，`vp9` 为 `webm`，或取 `transcode.format`） |
| `maxRetry`            | `number`                        | 每个分片的最大重试次数                                                                                       |
| `downloadConcurrency` | `number`                        | 分片并发下载数                                                                                               |
| `transcode`           | `HlsDownloaderTranscodeOptions` | BrowserAdapter 使用 WebCodecs 转码，NodeAdapter 使用 FFmpeg。省略时默认 transmux/remux                       |
| `signal`              | `AbortSignal`                   | 协作式取消。当信号中止时，下载 Promise 会被拒绝并抛出 `AbortError`                                           |
| _（适配器专有）_      | —                               | 见[适配器 API](/zh/api/adapters)                                                                             |

BrowserAdapter 支持 `preset`、`videoBitrate` 与 `audioBitrate`；NodeAdapter 支持下列全部字段：

| 字段           | 类型                        | 说明                  |
| -------------- | --------------------------- | --------------------- |
| `preset`       | `'h264' \| 'hevc' \| 'vp9'` | 编码预设              |
| `videoCodec`   | `string`                    | 覆盖预设视频编码      |
| `audioCodec`   | `string`                    | 覆盖预设音频编码      |
| `format`       | `string`                    | 输出容器（`-f`）      |
| `crf`          | `number`                    | 质量（x264/x265/vp9） |
| `videoBitrate` | `string \| number`          | 视频码率              |
| `audioBitrate` | `string \| number`          | 音频码率              |
| `speed`        | `HlsDownloaderEncoderSpeed` | x264/x265 编码速度    |

#### 示例：使用 AbortController 中止下载

```ts
const controller = new AbortController();

// 5 秒后中止（例如用户点击了取消）
setTimeout(() => controller.abort(), 5000);

try {
  await downloader.download({
    url: 'https://example.com/stream.m3u8',
    filename: 'output',
    signal: controller.signal,
  });
} catch (err) {
  if (err.name === 'AbortError') {
    console.log('下载已中止');
  } else {
    throw err;
  }
}
```

### `downloadToStream()`

带初始音视频偏移的外置音轨合流，已验证文件/Blob 播放。Chromium MSE 会忽略前置空 edit；接入 MSE 时，播放端必须分别映射各轨道时间戳，不能将这些合流字节原样追加到单个 SourceBuffer。SDK 不提供该 MSE 映射。

<Callout type="info" title="BrowserAdapter 与 NodeAdapter">
  `downloadToStream()` 在 **`BrowserAdapter`** 与 **`NodeAdapter`** 上均已实现。在 `BrowserAdapter`
  上，fMP4 字节通过 `onChunk` 推送，适合实时 MSE 播放（例如 `SourceBuffer.appendBuffer`）。
</Callout>

```ts
async downloadToStream(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions,
  onChunk: (bytes: Uint8Array) => void,
): Promise<HlsDownloaderStreamResult>
```

解析 HLS，经 Rust transmux 后通过 `onChunk` 推送 fMP4 字节。**库本身不落盘。** Browser 与 Node 均增量读取并输出分块。`onChunk` 为同步回调，不等待返回的 Promise 或 Node 下游的 `drain`；异步消费端请使用 `downloadToWritable()`。

输出为 **fragmented MP4**（首段 `ftyp`+`moov`，之后每段 `styp`+`moof`+`mdat`，不含末端 `mfra` 索引）。接入 MSE 时需遵守下述音轨时间戳限制。

单次传入的选项与 `globalOptions` 合并，单次选项优先。

| 选项                  | 类型                     | 描述                                                               |
| --------------------- | ------------------------ | ------------------------------------------------------------------ |
| `url`                 | `string`                 | HLS 播放列表地址                                                   |
| `headers`             | `Record<string, string>` | 请求头                                                             |
| `filename`            | `string`                 | 流式路径不写文件，此字段被忽略；为选项兼容性而保留                 |
| `maxRetry`            | `number`                 | 包含首次请求的总尝试次数；Browser 与 Node 流式路径均生效           |
| `operationId`         | `string`                 | 可选的事件关联 ID；省略时自动生成                                  |
| `downloadConcurrency` | `number`                 | 分片并发下载数                                                     |
| `signal`              | `AbortSignal`            | 协作式取消。当信号中止时，流式 Promise 会被拒绝并抛出 `AbortError` |

返回 `{ totalSegments: number, operationId: string }`。

#### 示例：HTTP 服务推流给浏览器（边推流 + 边落盘）

```ts
import { createServer } from 'node:http';
import { writeFile } from 'node:fs/promises';
import { HlsDownloader } from '@hls-downloader/core';
import { NodeAdapter } from '@hls-downloader/adapters/node';

const downloader = new HlsDownloader({ adapter: NodeAdapter });

const server = createServer(async (req, res) => {
  if (req.url !== '/stream.mp4') {
    res.writeHead(404);
    return res.end('not found');
  }

  res.writeHead(200, {
    'Content-Type': 'video/mp4', // fMP4，浏览器 MSE 可解析
    'Cache-Control': 'no-cache',
    // 不设 Content-Length —— 流式，长度未知
  });

  // 库本身不落盘：onChunk 拿到的字节同时写入 HTTP response 与文件
  const fileChunks: Uint8Array[] = [];
  await downloader.downloadToStream(
    {
      url: 'https://example.com/stream.m3u8',
      headers: { Authorization: 'Bearer ...' },
      downloadConcurrency: 8,
    },
    (bytes) => {
      res.write(bytes); // 边推流
      fileChunks.push(bytes); // 边缓冲（事后写文件）
    },
  );
  res.end();

  // 事后写文件（也可用 ReadableStream.tee() 在流过程中并行落盘）
  await writeFile('output.mp4', Buffer.concat(fileChunks.map((c) => Buffer.from(c))));
});

server.listen(3000);
```

<Callout type="info" title="边推流 + 边落盘的推荐做法">
若希望流过程中并行落盘（而非事后写），可把 `onChunk` 包装成 `ReadableStream`，再用 `stream.tee()` 分叉：
- branch 1 → HTTP response（实时播放）
- branch 2 → `Bun.write(filePath, branch)` 或 `pipeline(branch, createWriteStream(filePath))`（后台落盘）

`tee()` 内置背压与顺序保证，两个 branch 独立消费。task 完成后文件即可访问。

</Callout>

<Callout type="info" title="不支持 resume">
  流式路径写入的是不可 seek 的 sink，因此不支持 resume。若中途失败，需从头开始。
</Callout>

### `getPosterUrl()`

```ts
async getPosterUrl(
  options: HlsDownloaderFetchOptions
): Promise<string | undefined>
```

尝试从流中提取封面/缩略图 URL。会将 `options` 与 `globalOptions.download` 合并（仅 `headers`）。若存在则返回 URL 字符串，否则 `undefined`。

**`BrowserAdapter` 不会为此加载 FFmpeg。** `NodeAdapter` 仅在轻量提取失败时可能加载 — 见[适配器 API](/zh/api/adapters)。

| 选项      | 类型                     | 描述             |
| --------- | ------------------------ | ---------------- |
| `url`     | `string`                 | HLS 播放列表地址 |
| `headers` | `Record<string, string>` | 请求头           |

### `downloadToWritable()`

```ts
async downloadToWritable(
  options: HlsDownloaderWritableOptions,
  writable: WritableStream<Uint8Array>,
): Promise<HlsDownloaderStreamResult>
```

Browser 与 Node 均支持，按需下载并通过背压输出 fMP4，保留源编码。拒绝单次调用的 `transcode`，忽略全局转码设置。请检查 `downloader.capabilities.writableOutput === true`；缺少此可选能力的 adapter 在获取 writer 前报 `UNSUPPORTED_OUTPUT`。

库获取并管理 writer，等待每次写入，成功时关闭流；关闭完成后才发出 `READY_FOR_DOWNLOAD` 并 resolve。失败或取消会 abort writer 并释放锁。获取、写入、关闭失败使用 `OUTPUT_WRITE_FAILED`；取消使用 `ABORTED`，且 `name === 'AbortError'`。失败 operation 仅发一次 `ERROR`。自定义目标可能保留部分输出，库无法回滚任意外部写入；未结束的自定义 write 不会阻止库在取消时 reject，其后续 abort 结果会被异步处理。

`downloadConcurrency` 限制总读取并发；双路每路保留当前分片和一个 lookahead，另有初始化探测、当前输出分片及桥接缓冲。媒体缓冲不随视频总长度增长；playlist 元数据仍随分片数量增长，超大单分片仍需较多内存，WASM 内存会保留分配高水位。这不是固定 RSS 上限。fMP4 输出不包含尾部 `mfra` 索引。

`download()` 返回 Browser 全量 Blob URL 或 Node 文件；两端回调式 `downloadToStream()` 均增量读取媒体，但不等待回调 Promise，异步目标请使用 writable。`persistentOutput` 描述默认 `download()` 的结果，Browser 仍为 false；`writableOutput` 单独描述写入调用方目标的能力。

#### 直接保存文件

调用方在用户点击时打开选择器并传入写入流。应用自行检查 File System Access 可用性与权限；库不弹窗，也不自动回退为全量 Blob。以下示例假定页面有 `#save`、`#cancel` 按钮且浏览器提供 `showSaveFilePicker`；AbortController 取消后不可复用，新 operation 应创建新的 controller。

```js
import { HlsDownloader } from '@hls-downloader/core';
import { BrowserAdapter } from '@hls-downloader/adapters/browser';

const downloader = new HlsDownloader({ adapter: BrowserAdapter });
const controller = new AbortController();
// Invoke directly from a user click; do not await library initialization first.
document.querySelector('#save').addEventListener('click', async () => {
  try {
    const handle = await window.showSaveFilePicker({
      suggestedName: 'video.mp4',
      types: [{ description: 'MP4 video', accept: { 'video/mp4': ['.mp4'] } }],
    });
    const writable = await handle.createWritable();
    await downloader.downloadToWritable(
      { url: 'https://example.com/video.m3u8', signal: controller.signal },
      writable,
    );
  } catch (error) {
    console.error('Download or saving failed', error);
  }
});
document.querySelector('#cancel').addEventListener('click', () => controller.abort());
```

### Node 可恢复下载（v3.6）

```ts
import { HlsDownloader } from '@logosw/hls-downloader/core';
import { NodeAdapter, type NodeAdapterResumeOptions } from '@logosw/hls-downloader/adapters/node';

const downloader = new HlsDownloader({ adapter: NodeAdapter });
const resume: NodeAdapterResumeOptions = { directory: './download-jobs/video' };
const result = await downloader.download({
  url: 'https://example.com/media.m3u8',
  filename: 'video',
  resume,
  signal: new AbortController().signal,
});
// After interruption, call download again with the same options and a new signal.
```

`resume` 仅用于 Node 单次 `download()`。相对目录及输出文件名按调用时工作目录解析，每个任务使用独立空目录。支持普通 VOD TS/fMP4，以及 BYTERANGE 和 MAP；与单次或全局转码、启用的 aria2 组合时返回 `UNSUPPORTED_OUTPUT`。Browser、回调流和 writable 输出不支持恢复。

中断后保持原始 URL（包含签名参数）、实际请求头、variant 选择及输出目标不变，再次调用即可恢复；可以修改 `operationId`、signal、重试次数和并发数。下载阶段会重新获取播放列表，要求内容和解析后的地址不变；不一致时返回 `RESUME_INVALID` 并保留现场。需要更换输入时使用新目录。已进入 finalize 或已完成的任务使用本地数据恢复，不请求 manifest。

缓存命中会校验长度和 SHA-256，损坏项重新下载。哈希验证本地数据完整性，不保证远端同一 URL 的内容不变，因此要求输入为稳定 VOD。进度完成数包含已提交分片，最终文件交付后才发出 `READY_FOR_DOWNLOAD` 并完成 Promise。

失败或取消保留有效恢复数据并释放目录锁。成功后清理分片缓存及 partial 输出，保留锁文件和少量完成凭据；再次调用会验证并返回已完成文件，不重新下载。清理失败不会使已交付的输出变成失败。`clearCache()` 不清理恢复目录；放弃或遗忘任务时由调用方删除专用目录。持久化保证受操作系统和文件系统限制。

| 错误码             | 含义                                                           |
| ------------------ | -------------------------------------------------------------- |
| `RESUME_CONFLICT`  | 其他进程或 operation 正在使用恢复目录。                        |
| `RESUME_INVALID`   | 目录或 checkpoint 无效、输入身份变化、已完成输出丢失或被修改。 |
| `RESUME_IO_FAILED` | 恢复存储、checkpoint 保存或输出交付失败。                      |
| `ABORTED`          | 下载取消，保留 `name === 'AbortError'`。                       |

## 浏览器请求选项

BrowserAdapter 的六个媒体方法均接受 `browserRequest`，单次配置整体替换实例 `options.browserRequest`，`{}` 恢复原生默认值。播放列表和封面结果不跨调用复用，`clearCache()` 对浏览器为 no-op。详见 [Adapter API](/api/adapters#浏览器媒体请求上下文)。

### 音轨选择与 WebVTT 字幕

```ts
const source = { url: 'https://example.test/master.m3u8' };
const parsed = await downloader.parseHls(source);
if (parsed.type === 'playlist') console.log(parsed.renditions);

await downloader.downloadToWritable(
  { ...source, audio: { language: 'en' } },
  destination, // WHATWG WritableStream<Uint8Array>
);
const subtitles = await downloader.downloadSubtitles({
  ...source,
  audio: { language: 'en' },
  subtitle: { groupId: 'subs', name: 'English' },
});
console.log(subtitles.text); // save as subtitles.filename
```

先选择 variant，再在其关联的音频组内选轨。未显式指定时按 DEFAULT、AUTOSELECT、声明顺序选择。外置音轨替换内嵌音频；无 URI 的 rendition 保留内嵌音频，最终输出一条所选音轨。备用视频组明确失败。

备用音轨支持明文、AES-128 及 adapter API 列出的 sample 解密组合，输入为有限 VOD TS/fMP4；不兼容 resume、转码或 aria2。未选择的字幕不会请求。省略 `timeline` 时，两路必须共享可确定的时间轴，时间戳重置或不可表达的间隙会失败。显式 `timeline` 可启用下述 epoch 与缺口策略。

`downloadSubtitles()` 是独立 operation，导出一条外置 WebVTT。它先探测所选媒体的初始化数据/首段以取得共同时间轴，再读取字幕。支持 MAP、时间戳映射与回绕、空分片、cue 去重和设置保留。输出零点前的 cue 被丢弃或截到零点；非法字幕报 `SUBTITLE_INVALID`。不内嵌字幕，也不转换 SRT。

Node writable 接受 WHATWG 流。已有 Node writable 可通过 `node:stream` 的 `Writable.toWeb(nodeWritable)` 转换；operation 期间由 downloader 管理 close/abort。

### `parseMediaPlaylist(text, url)`

```ts
const playlist = await downloader.parseMediaPlaylist(text, finalPlaylistUrl);
const sequence = BigInt(playlist.segments[0].originalSequence);
```

从已选媒体清单的原始文本及最终 URL 解析版本化 `HlsMediaPlaylist` 元数据，保留十进制字符串的 sequence/range/ticks、KEY 候选、MAP 声明上下文、NONE 切换、gap 和 discontinuity。此方法不选择 master rendition，也不请求 key/media。Browser 可为解析器加载 WASM；原有轻量 `parseHls()` 行为保持不变。解析成功不代表媒体可执行。

## 时间范围与多输出

`download()`、`downloadToStream()` 和 `downloadToWritable()` 通过显式 `timeline` 启用有限时间轴路径，省略时保留原路由和启动行为。时间使用无损的 `{ ticks: string, timescale: number }`。范围为公共 presentation timeline 的半开区间；视频扩展至经过验证的独立解码点，并保留必要 preroll 和尾部 GOP。结束位置超出 EOF 会裁到可用媒体；空、完全越界或无法解码的范围返回 `RANGE_INVALID`。

```ts
const result = await downloader.download({
  url: 'https://example.com/media.m3u8',
  timeline: {
    range: { start: { ticks: '5', timescale: 1 }, end: { ticks: '12', timescale: 1 } },
    gapPolicy: 'preserve',
  },
});
console.log(result.timelineReport?.actual);
```

返回值新增 `timelineReport`，包含请求/实际区间、可选 preroll/postroll 区间、各输出的轨道/epoch 映射、依赖及读取/规划计数。`schemaVersion: 1` 是诊断 JSON，不是 checkpoint。`totalSegments` 统计输出媒体资源，同一资源用于多个子输出时可能重复计数。协议级计数和索引均保留十进制字符串。

默认 `gapPolicy: 'preserve'` 保留可表达的缺口；`'collapse'` 仅移除所选轨道共同缺失的区间。单输出遇到配置变化或不可表达的缺口会失败。`epochAnchors: [{ inputId, epoch, source, presentation }]` 提供明确重置依据，inputId 为 `primary` 或可选 `audio`；时钟有歧义时失败，不按 rendition sequence 猜测同步。`tailDuration` 是源证据不足时显式提供的正数媒体时长。

`timeline.limits` 默认允许 65,536 个 sample 记录和 4,096 个游标资源。资源/key 预算仍使用 `decryption.limits`，明文时间轴也适用。首次输出前完成有限扫描和验证，可能重复读取媒体；资源字节或解密包发生变化返回 `RESOURCE_CHANGED`。预算不是总 RSS 上限：有限目录、报告、classic MP4 缓冲和索引另有成本。

### `downloadOutputs(options)`

独立多输出 API 返回 `{ operationId, totalSegments, outputs, timelineReport }`。每个输出包含十进制字符串 `index`，以及 Browser 的 `blobURL` 或 Node 的 `filePath`，格式为 classic MP4。Node 命名为 `basename.001.mp4`、`basename.002.mp4` 等。Browser 在全部输出成功后才创建 Blob URL，使用结束后由调用方 revoke。

通过 `timeline: { changePolicy: 'split' }` 在可解码边界拆分配置变化或不可表达的缺口；默认仍为 `'fail'`。fMP4 可直接表达的 gap 不会强制拆分。既有单输出 API 不接受该策略。

### `downloadToWritables(options, outputFactory)`

```ts
const result = await downloader.downloadToWritables(
  { url, timeline: { changePolicy: 'split' } },
  async ({ index, actualRange, reason, tracks }) => {
    return await createDestination(index); // Promise<WritableStream<Uint8Array>>
  },
);
```

工厂在有限验证后调用，每次返回独立 fMP4 目标；先获取下一个目标，再完成当前输出。每次写入等待背压，公共完成等待目标 close。下一个目标获取失败时，当前输出不会标记完成。取消会 abort 已获取但未完成的 writer，迟到工厂返回的流也会被 abort。失败的 `completedOutputs` 仅包含已发布文件或成功关闭的 writable，保留这些可用产物；部分 writer 不是恢复 checkpoint。

时间轴路径不支持 resume、转码或 aria2。writable 继续忽略全局转码默认值，拒绝单次转码选项。旧明文单路恢复继续在 timeline 之外使用。callback stream 仍不等待回调 Promise。合流 fMP4 不保证可直接用于 MSE，必要时播放端仍需分别映射轨道时间戳。

## 时间轴字幕与章节 sidecar

`downloadSubtitleOutputs({ url, subtitle, timelineReport, track?, filename? })` 使用同一来源/选轨的已完成报告导出有限**明文** WebVTT，返回 `{ operationId, totalSegments, outputs }`。每个 sidecar 包含 `outputIndex`、`text`、`filename` 和 `mimeType: 'text/vtt'`。只获取清单及字幕资源，不重新解码主媒体；结合 X-TIMESTAMP-MAP 和可用 PDT 证据解析时钟，重置有歧义时返回 `SUBTITLE_INVALID`。

`exportChapters({ chapters, timelineReport, track?, filename? })` 是根包/shared 的同步命名导出。章节为公共时间轴上的 `{ range: { start, end }, title, id? }`，按每个输出返回 WebVTT chapters。两种操作默认跟随主视频轨，纯音频输出跟随主音频轨；`track: { inputId, trackId }` 可显式选择报告映射。区间在映射边界裁切/拆分并转换为输出时间，最后序列化为毫秒 WebVTT 时间戳；不会自动写入 sidecar 文件。

既有 `downloadSubtitles()` 不变。暂不支持字幕资源解密及字幕内嵌。

## startRecording

`startRecording(options)` 同步返回录制句柄，包含 `result`、`stop`、`cancel`、VOD `pause`/`resume` 和独立输入控制。必须显式选择输出；现有下载入口仍限于有限输入。见[Adapter 录制 API](/api/adapters#持续录制)。

## 固定多轨下载与录制

`downloadMultiTrack(options)` 接受所选播放列表均已 ENDLIST 的有限输入。`startMultiTrackRecording(options)` 返回 VOD、Live、EVENT 会话，提供 `result`、`stop()`、`cancel()`、仅 VOD 可用的 `pause()` / `resume()`，以及 `endInput(id)`、`restartInput(id, { generation, url? })`。一次任务的选轨固定。现有 `download()`、`startRecording()` 及单个 `audio` 替换音轨选项保持原语义。

```ts
const result = await downloader.downloadMultiTrack({
  url: 'https://example.com/master.m3u8',
  embeddedAudio: 'exclude',
  audioTracks: [
    { id: 'english', selector: { language: 'en' } },
    { id: 'japanese', selector: { groupId: 'audio', name: 'Japanese' } },
  ],
  subtitleTracks: [
    { id: 'captions', selector: { groupId: 'subs', name: 'English' } },
  ],
  output: { type: 'writable', writable },
});
console.log(result.report.tracks, result.report.subtitleReports);
```

必须显式指定 `embeddedAudio`：`keep` 保留主路音频，`exclude` 排除主路音频。`audioTracks`、`subtitleTracks` 默认空数组，不自动选入其他 rendition。每项 `id` 唯一，允许 1–128 个 ASCII 字母、数字、`_`、`.`、`:`、`-`，`primary` 为保留值。音轨使用原有的语言精确匹配（忽略大小写）或 group/name 匹配，同语言候选沿用 default/autoselect 优先规则；字幕使用 group/name。只能选择当前 variant 关联 group 的轨道；直接媒体 URL 可用作主输入，但不能指定 rendition selector。无 URI 的主路音频由 `embeddedAudio` 控制；重复资源拒绝执行。

可选 `metadata: { language, name, default }` 覆盖 rendition 元数据，`primaryAudio` 描述保留的主路音频。音频和字幕各最多一个默认轨；没有显式或继承的默认音轨时，上游选择第一条音轨。字幕 `timelineInputId` 默认 `primary`，必须指向所选媒体输入。分割输出保留轨道身份，restart 只改变媒体输入 generation，不改变选轨；绑定字幕已经结束时拒绝 restart。

输出沿用录制所有权：Browser 支持 `{ type: 'blob', maxBytes, format?: 'mp4' | 'fmp4' }`、`writable`、`writables`；Node 支持 `file`、`files`、`writable`、`writables`。Blob/文件默认经典 MP4，writable 始终输出 fMP4。Blob 必须指定正数内存上限，文件不会覆盖已有目标。分割策略必须使用 `files` / `writables` factory。完成状态晚于 writable close；stop 排空已接收媒体及字幕尾部，cancel 中止待处理工作。有限下载要求全部媒体和字幕播放列表都有 ENDLIST，包括已经结束的 EVENT 快照。

新入口沿用录制的 `timeline`、`missingSegments`、`durationLimit`、`limits`；锚点可使用任意所选媒体 ID。字幕使用 `X-TIMESTAMP-MAP`（缺省采用 WebVTT 零映射）、对应 discontinuity epoch 和精确媒体源时钟；不以分片序号或 EXTINF 猜测同步。33 位回绕无法明确解析时需提供显式 source anchor；绑定缺失或时钟不明确时报 `SUBTITLE_INVALID`。

SDK 在对应媒体快照之前有界读取并接收字幕快照。初始可见 cue 集须能放入本次 sample/byte 预算；超限立即失败，不等待尚未启动的消费者。后续容量等待允许媒体继续前进，所有字幕轨额外只保留一批待接收数据。初始所选 manifest 还共享 `limits.queuedMetadataBytes`，默认 4 MiB。慢 writable 阻止新轮询，已开始工作仍受预算限制；报告历史有界，并提供明确截断标记。

内嵌字幕支持 UTF-8 纯文本、identifier 和 `align`、`position`、`line`、`size`、`vertical`。STYLE、REGION、markup、重复或非法 settings、加密字幕均拒绝。自动行位置应省略 `line`；显式 `line:auto`、`position:80%,auto` 不受支持。重叠和空区间以 wvtt 表示；完全迟到 cue 报告为拒绝，部分迟到 cue 裁剪。已接收字幕尾部独立于媒体 EOF 排空，并受请求范围约束。现有 WebVTT sidecar 导出保持独立格式支持。

`report` 在媒体统计之外增加 `configurationId`、`tracks`、`subtitleReports`、`trackHistoryTruncated`、`subtitleHistoryTruncated`。轨道记录包含稳定输出/input ID、输出索引、种类、编码、元数据、timescale、时长及 sample 数；字幕记录含实际输出区间及 `Written`、`Clipped`、`RejectedLate`。`subtitles` 事件提供接收数量，事件携带 `operationId`。宽整数继续使用十进制字符串。错误提供 `completedMultiTrackOutputs`、`multiTrackHistoryTruncated`；报告不能用于持久恢复。

`playbackTarget` 默认 `container`。指定 `direct-browser`、`avfoundation`、`vlc`、`iina`、`ffmpeg` 时执行上游播放能力检查，不支持的组合报 `UNSUPPORTED_OUTPUT` 并附明确 `reason`。容器正确不代表播放器能选择或渲染所有轨道：浏览器 Blob/MSE 直接播放拒绝；VLC 完整字幕 settings、IINA/FFmpeg wvtt、IINA/FFmpeg 经典 MP4 edit-list 播放存在限制；原生播放器目标存在 decode gap 时拒绝。本轮不提供播放器、字幕提取服务或自动回退。
