用于下载 HLS 流的主门面类。从 `@hls-downloader/core` 导入。

<Callout type="info" title="默认下载路径（Transmux）">
**普通 `download()` 会保留源编码并 transmux 为 MP4。** BrowserAdapter 使用 [hls-engine](https://github.com/Logosww/hls-engine) WebAssembly；NodeAdapter 使用原生 Rust 路径。

重编码通过 `transcode` 显式启用 — 见[适配器 API](/zh/api/adapters)。BrowserAdapter 使用 Mediabunny 与 WebCodecs；NodeAdapter 按需加载原生 FFmpeg。`init()` 与 `parseHls()` 均不会启动这些引擎。

</Callout>

## 构造函数

```ts
new HlsDownloader({
  adapter,
  options?,
  onEvent?,
})
```

| 参数      | 类型                            | 描述                                                                       |
| --------- | ------------------------------- | -------------------------------------------------------------------------- |
| `adapter` | `BrowserAdapter \| NodeAdapter` | 使用的适配器                                                               |
| `options` | `GlobalOptions<T>`              | 默认选项（见下文），会与每次 `parseHls` / `download` / `getPosterUrl` 合并 |
| `onEvent` | `(event, payload?) => void`     | 事件回调，用于追踪进度和错误                                               |

## 属性

### `isInit`

```ts
get isInit(): boolean
```

适配器是否已完成初始化。`init()` 成功后为 `true`。

### `globalOptions`

```ts
get globalOptions(): GlobalOptions<T> | null
```

当前默认选项；未设置时为 `null`。

## GlobalOptions

从 `@hls-downloader/core` 导出为 `GlobalOptions<T>`，具体字段随适配器类型 `T` 变化。

| 字段             | 类型                                 | 描述                                      |
| ---------------- | ------------------------------------ | ----------------------------------------- |
| `download`       | `HlsDownloaderGlobalDownloadOptions` | 默认请求 / 下载相关选项（不含单次 `url`） |
| `transcode`      | `HlsDownloaderTranscodeOptions`      | 默认转码选项                              |
| _（适配器专有）_ | —                                    | 见[适配器 API](/zh/api/adapters)          |

### `download` 对象

| 字段          | 类型                     | 描述                     |
| ------------- | ------------------------ | ------------------------ |
| `headers`     | `Record<string, string>` | 默认请求头               |
| `concurrency` | `number`                 | 默认分片并发下载数       |
| `maxRetry`    | `number`                 | 默认每个分片最大重试次数 |

单次调用 `download({ downloadConcurrency })` 会覆盖 `download.concurrency`。

## 方法

### `init()`

```ts
async init(): Promise<void>
```

初始化轻量适配器状态。BrowserAdapter 与 NodeAdapter 仅在后续 API 需要时才启动其重量级引擎。`download()` 会在未初始化时自动触发 `init()`。

### `setOptions()`

```ts
setOptions(options: GlobalOptions<T>): void
```

更新默认选项，结构与构造函数 `options` 相同。

### `parseHls()`

```ts
async parseHls(options: HlsDownloaderFetchOptions): Promise<ParseHlsResult>
```

仅解析 HLS 播放列表，不下载分片。会将 `options` 与 `globalOptions.download` 合并（仅 `headers`）。

返回 `ParseHlsResult`：

- `{ type: 'playlist', data: Playlist[] }` — 主列表及变体流
- `{ type: 'segment', data: Segment[] }` — 媒体列表及分片
- `{ type: 'error', message: string }` — 解析错误

| 选项      | 类型                     | 描述             |
| --------- | ------------------------ | ---------------- |
| `url`     | `string`                 | HLS 播放列表地址 |
| `headers` | `Record<string, string>` | 请求头           |

### `download()`

```ts
async download(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions & Partial<AdapterOptions>
): Promise<DownloadResult>
```

解析、下载全部分片并合并为单个文件。成功时：**`BrowserAdapter`** 解析为 `{ blobURL, totalSegments }`；**`NodeAdapter`** 解析为 `{ filePath, totalSegments }`。失败时 Promise 被拒绝。

**默认（不传 `transcode`）** 各适配器走 transmux 路径并保留源编码。传入 `transcode` 后进入重编码：BrowserAdapter 使用 WebCodecs；NodeAdapter 使用 FFmpeg。

单次传入的选项与 `globalOptions` 合并，单次选项优先。

| 选项                  | 类型                            | 描述                                                                                                         |
| --------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `url`                 | `string`                        | HLS 播放列表地址                                                                                             |
| `headers`             | `Record<string, string>`        | 请求头                                                                                                       |
| `filename`            | `string`                        | 不含扩展名的输出文件名。扩展名由内部根据输出容器解析（默认 `mp4`，`vp9` 为 `webm`，或取 `transcode.format`） |
| `maxRetry`            | `number`                        | 每个分片的最大重试次数                                                                                       |
| `downloadConcurrency` | `number`                        | 分片并发下载数                                                                                               |
| `transcode`           | `HlsDownloaderTranscodeOptions` | BrowserAdapter 使用 WebCodecs 转码，NodeAdapter 使用 FFmpeg。省略时默认 transmux/remux                       |
| `signal`              | `AbortSignal`                   | 协作式取消。当信号中止时，下载 Promise 会被拒绝并抛出 `AbortError`                                           |
| _（适配器专有）_      | —                               | 见[适配器 API](/zh/api/adapters)                                                                             |

BrowserAdapter 支持 `preset`、`videoBitrate` 与 `audioBitrate`；NodeAdapter 支持下列全部字段：

| 字段           | 类型                        | 说明                  |
| -------------- | --------------------------- | --------------------- |
| `preset`       | `'h264' \| 'hevc' \| 'vp9'` | 编码预设              |
| `videoCodec`   | `string`                    | 覆盖预设视频编码      |
| `audioCodec`   | `string`                    | 覆盖预设音频编码      |
| `format`       | `string`                    | 输出容器（`-f`）      |
| `crf`          | `number`                    | 质量（x264/x265/vp9） |
| `videoBitrate` | `string \| number`          | 视频码率              |
| `audioBitrate` | `string \| number`          | 音频码率              |
| `speed`        | `HlsDownloaderEncoderSpeed` | x264/x265 编码速度    |

#### 示例：使用 AbortController 中止下载

```ts
const controller = new AbortController();

// 5 秒后中止（例如用户点击了取消）
setTimeout(() => controller.abort(), 5000);

try {
  await downloader.download({
    url: 'https://example.com/stream.m3u8',
    filename: 'output',
    signal: controller.signal,
  });
} catch (err) {
  if (err.name === 'AbortError') {
    console.log('下载已中止');
  } else {
    throw err;
  }
}
```

### `downloadToStream()`

带初始音视频偏移的外置音轨合流，已验证文件/Blob 播放。Chromium MSE 会忽略前置空 edit；接入 MSE 时，播放端必须分别映射各轨道时间戳，不能将这些合流字节原样追加到单个 SourceBuffer。本库不提供该 MSE 映射。

<Callout type="info" title="BrowserAdapter 与 NodeAdapter">
  `downloadToStream()` 在 **`BrowserAdapter`** 与 **`NodeAdapter`** 上均已实现。在 `BrowserAdapter`
  上，fMP4 字节通过 `onChunk` 推送，适合实时 MSE 播放（例如 `SourceBuffer.appendBuffer`）。
</Callout>

```ts
async downloadToStream(
  options: HlsDownloaderFetchOptions & HlsDownloaderDownloadOptions,
  onChunk: (bytes: Uint8Array) => void,
): Promise<HlsDownloaderStreamResult>
```

解析 HLS，经 Rust transmux 后通过 `onChunk` 推送 fMP4 字节。**库本身不落盘。** Browser 与 Node 均增量读取并输出分块。`onChunk` 为同步回调，不等待返回的 Promise 或 Node 下游的 `drain`；异步消费端请使用 `downloadToWritable()`。

输出为 **fragmented MP4**（首段 `ftyp`+`moov`，之后每段 `styp`+`moof`+`mdat`，不含末端 `mfra` 索引）。接入 MSE 时需遵守下述音轨时间戳限制。

单次传入的选项与 `globalOptions` 合并，单次选项优先。

| 选项                  | 类型                     | 描述                                                               |
| --------------------- | ------------------------ | ------------------------------------------------------------------ |
| `url`                 | `string`                 | HLS 播放列表地址                                                   |
| `headers`             | `Record<string, string>` | 请求头                                                             |
| `filename`            | `string`                 | 流式路径不写文件，此字段被忽略；为选项兼容性而保留                 |
| `maxRetry`            | `number`                 | 包含首次请求的总尝试次数；Browser 与 Node 流式路径均生效           |
| `operationId`         | `string`                 | 可选的事件关联 ID；省略时自动生成                                  |
| `downloadConcurrency` | `number`                 | 分片并发下载数                                                     |
| `signal`              | `AbortSignal`            | 协作式取消。当信号中止时，流式 Promise 会被拒绝并抛出 `AbortError` |

返回 `{ totalSegments: number, operationId: string }`。

#### 示例：HTTP 服务推流给浏览器（边推流 + 边落盘）

```ts
import { createServer } from 'node:http';
import { writeFile } from 'node:fs/promises';
import { HlsDownloader } from '@hls-downloader/core';
import { NodeAdapter } from '@hls-downloader/adapters/node';

const downloader = new HlsDownloader({ adapter: NodeAdapter });

const server = createServer(async (req, res) => {
  if (req.url !== '/stream.mp4') {
    res.writeHead(404);
    return res.end('not found');
  }

  res.writeHead(200, {
    'Content-Type': 'video/mp4', // fMP4，浏览器 MSE 可解析
    'Cache-Control': 'no-cache',
    // 不设 Content-Length —— 流式，长度未知
  });

  // 库本身不落盘：onChunk 拿到的字节同时写入 HTTP response 与文件
  const fileChunks: Uint8Array[] = [];
  await downloader.downloadToStream(
    {
      url: 'https://example.com/stream.m3u8',
      headers: { Authorization: 'Bearer ...' },
      downloadConcurrency: 8,
    },
    (bytes) => {
      res.write(bytes); // 边推流
      fileChunks.push(bytes); // 边缓冲（事后写文件）
    },
  );
  res.end();

  // 事后写文件（也可用 ReadableStream.tee() 在流过程中并行落盘）
  await writeFile('output.mp4', Buffer.concat(fileChunks.map((c) => Buffer.from(c))));
});

server.listen(3000);
```

<Callout type="info" title="边推流 + 边落盘的推荐做法">
若希望流过程中并行落盘（而非事后写），可把 `onChunk` 包装成 `ReadableStream`，再用 `stream.tee()` 分叉：
- branch 1 → HTTP response（实时播放）
- branch 2 → `Bun.write(filePath, branch)` 或 `pipeline(branch, createWriteStream(filePath))`（后台落盘）

`tee()` 内置背压与顺序保证，两个 branch 独立消费。task 完成后文件即可访问。

</Callout>

<Callout type="info" title="不支持 resume">
  流式路径写入的是不可 seek 的 sink，因此不支持 resume。若中途失败，需从头开始。
</Callout>

### `getPosterUrl()`

```ts
async getPosterUrl(
  options: HlsDownloaderFetchOptions
): Promise<string | undefined>
```

尝试从流中提取封面/缩略图 URL。会将 `options` 与 `globalOptions.download` 合并（仅 `headers`）。若存在则返回 URL 字符串，否则 `undefined`。

**`BrowserAdapter` 不会为此加载 FFmpeg。** `NodeAdapter` 仅在轻量提取失败时可能加载 — 见[适配器 API](/zh/api/adapters)。

| 选项      | 类型                     | 描述             |
| --------- | ------------------------ | ---------------- |
| `url`     | `string`                 | HLS 播放列表地址 |
| `headers` | `Record<string, string>` | 请求头           |

### `downloadToWritable()`

```ts
async downloadToWritable(
  options: HlsDownloaderWritableOptions,
  writable: WritableStream<Uint8Array>,
): Promise<HlsDownloaderStreamResult>
```

Browser 与 Node 均支持，按需下载并通过背压输出 fMP4，保留源编码。拒绝单次调用的 `transcode`，忽略全局转码设置。请检查 `downloader.capabilities.writableOutput === true`；缺少此可选能力的 adapter 在获取 writer 前报 `UNSUPPORTED_OUTPUT`。

库获取并管理 writer，等待每次写入，成功时关闭流；关闭完成后才发出 `READY_FOR_DOWNLOAD` 并 resolve。失败或取消会 abort writer 并释放锁。获取、写入、关闭失败使用 `OUTPUT_WRITE_FAILED`；取消使用 `ABORTED`，且 `name === 'AbortError'`。失败 operation 仅发一次 `ERROR`。自定义目标可能保留部分输出，库无法回滚任意外部写入；未结束的自定义 write 不会阻止库在取消时 reject，其后续 abort 结果会被异步处理。

`downloadConcurrency` 限制总读取并发；双路每路保留当前分片和一个 lookahead，另有初始化探测、当前输出分片及桥接缓冲。媒体缓冲不随视频总长度增长；playlist 元数据仍随分片数量增长，超大单分片仍需较多内存，WASM 内存会保留分配高水位。这不是固定 RSS 上限。fMP4 输出不包含尾部 `mfra` 索引。

`download()` 返回 Browser 全量 Blob URL 或 Node 文件；两端回调式 `downloadToStream()` 均增量读取媒体，但不等待回调 Promise，异步目标请使用 writable。`persistentOutput` 描述默认 `download()` 的结果，Browser 仍为 false；`writableOutput` 单独描述写入调用方目标的能力。

#### 直接保存文件

调用方在用户点击时打开选择器并传入写入流。应用自行检查 File System Access 可用性与权限；库不弹窗，也不自动回退为全量 Blob。以下示例假定页面有 `#save`、`#cancel` 按钮且浏览器提供 `showSaveFilePicker`；AbortController 取消后不可复用，新 operation 应创建新的 controller。

```js
import { HlsDownloader } from '@hls-downloader/core';
import { BrowserAdapter } from '@hls-downloader/adapters/browser';

const downloader = new HlsDownloader({ adapter: BrowserAdapter });
const controller = new AbortController();
// Invoke directly from a user click; do not await library initialization first.
document.querySelector('#save').addEventListener('click', async () => {
  try {
    const handle = await window.showSaveFilePicker({
      suggestedName: 'video.mp4',
      types: [{ description: 'MP4 video', accept: { 'video/mp4': ['.mp4'] } }],
    });
    const writable = await handle.createWritable();
    await downloader.downloadToWritable(
      { url: 'https://example.com/video.m3u8', signal: controller.signal },
      writable,
    );
  } catch (error) {
    console.error('Download or saving failed', error);
  }
});
document.querySelector('#cancel').addEventListener('click', () => controller.abort());
```

## 统一 Engine 输出

所有 HLS 下载、流式输出、时间线及录制入口统一使用 `hls-engine 1.0`，保留现有方法名。
FFmpeg/WebCodecs 仍负责独立的转码路径。有限下载要求每个选定输入均有 ENDLIST；
`startRecording()` 和 `startMultiTrackRecording()` 支持 Live/EVENT 清单刷新。

结果通过 `report: HlsEngineReport` 返回输入进度、轨道、字幕回执、完成输出、请求/实际区间、
有界映射及历史截断标记。协议计数、generation、sequence 和 ticks 保持十进制字符串，
精确运算使用 `BigInt`。已移除 `timelineReport` 及完整资源/sample 索引契约。

`download()` 默认选择外部默认音轨，也可用 `audio` 指定。
`downloadMultiTrack()` 显式传入 `embeddedAudio: 'keep' | 'exclude'`，并支持
`audioTracks`、`subtitleTracks` 和 `playbackTarget`；不会读取未选中的 rendition。
`parseMediaPlaylist(text, url)` 无网络解析无损元数据，`parseHls()` 继续提供选流及选轨信息。

Browser `download({ url, maxBytes? })` 的默认收集上限为 **256 MiB**。
录制的 `{ type: 'blob', maxBytes }` 必须显式指定容量。容量限制收集字节，不是进程总内存上限，
也不包括 classic MP4 索引的全部开销。Writable 逐次等待 write 和 close；
callback `downloadToStream()` 不等待回调返回的 Promise。

`downloadOutputs()` 返回 `{ operationId, totalSegments, outputs, report }`。
Browser 返回 fMP4 Blob URL，Node 返回 classic MP4，文件名依次为
`basename.001.mp4`、`basename.002.mp4`。Blob URL 用后需 revoke。
`downloadToWritables()` 使用工厂获取每个 sink；分割通过 `timeline.changePolicy: 'split'`
开启，单个借用 Writable 不能分割。失败的 `error.completedOutputs` 保留已发布文件及
已成功关闭的 Writable。READY/result 完成必须等待目标关闭。

## 持续 WebVTT sidecar

`downloadMultiTrack()` 和 `startMultiTrackRecording()` 支持明文及 AES-128 WebVTT
segment/MAP，包括密钥轮换和原始 sequence IV。字幕与媒体共用 operation 的 key session、
取消及资源预算。SAMPLE-AES、CTR、GCM WebVTT 仍不支持；持续路径仅支持纯文本与标准
cue settings，不支持样式块及富文本 cue 标记。

```ts
const session = downloader.startMultiTrackRecording({
  url,
  embeddedAudio: 'keep',
  subtitleTracks: [{
    id: 'english',
    selector: { groupId: 'subs', name: 'English' },
    embedded: false,
    sidecar: { type: 'writable', writable: subtitleWritable },
  }],
  output: { type: 'writable', writable: mediaWritable },
  onEvent(event) {
    if (event.type === 'subtitleCommit') console.log(event.commit.frontiers);
  },
});
// 需要结束时：session.stop(); await session.result;
```

两端均等待字幕 write 和 close。`embedded` 默认 `true`；设为 `false` 时必须提供 sidecar，
容器不再内嵌 wvtt。拆分时，为每条字幕选择提供
`{ type: 'writables', acquire: async ({ inputId, outputIndex }) => writable }`。
各 writer 必须与媒体及其他活动字幕 writer 独立；前一分卷关闭后才获取下一分卷。
单个借用 Writable 不支持 split。

每个输出写入一次 UTF-8 `WEBVTT` 头。cue 使用实际提交的输出时间轴，随范围裁切和分卷重定位，
跨提交窗口的 cue 可分段输出。时间戳向下取整到毫秒，量化后为空的片段不输出。
`subtitleCommit` 提供精确有理数时间、receipt、轨道/输入、generation/epoch、分卷、裁切或拒绝
结果及提交水位。该事件仅用于观察；回调返回值不提供背压或持久化确认，确认由 sidecar sink
完成。stop 排空已接受工作；cancel 不等待不响应的 sink，迟到写入不会把取消变为成功。
写入/关闭失败返回 `OUTPUT_WRITE_FAILED`；已经确认写入的 Writable 字节不能回滚。

Node 的固定媒体文件输出还支持 `sidecar: { type: 'file', path: './english.vtt' }`。
启用 `resume: { directory: './job' }` 时，每条选中字幕均须配置固定 sidecar 文件；
Writable/工厂不能恢复。保留已有的无关文件。首个输出使用指定路径，后续使用
`<path>.part-000001.vtt`，与媒体的 `.part-000001.mp4` 分卷对应。
发布逐文件完成，不承诺多个文件的原子重命名。

本库的 checkpoint 外层仍为 schema 2；媒体/字幕联合恢复使用 Engine 内层 archive schema 3，
仅媒体 archive 仍为 schema 2。截去未提交尾部前，校验全部已提交前缀并重新读取字幕资源。
加密恢复要求 key resolver 提供稳定 `version`。目标路径/配置变更返回 `RESUME_CONFLICT`，
前缀损坏返回 `RESUME_INVALID`；重放资源或密钥版本缺失/变更可能返回
`RESUME_REPLAY_REQUIRED`。不持久化原始密钥；完成态可离线恢复。
完成态持久化前保留任务目录及 partial 文件。字幕重放元数据共用有界恢复日志
（`limits.queuedMetadataBytes`），耗尽返回 `RESOURCE_LIMIT_EXCEEDED`，不承诺无限恢复历史。

`downloadSubtitles()` 和 `downloadSubtitleOutputs()` 同时支持 `decryption` 和 `maxBytes`
（收集的 UTF-8 字幕数据默认上限 16 MiB）。后者使用调用方提供的完整 timeline map，
只读取字幕资源。这两个有限导出接口本身不启用持续录制。
`capabilities.multiTrack` 的 `subtitleResources`、`subtitleSidecars` 描述新增能力；
`queryCapability()` 请求中的 `subtitles` 指内嵌字幕，继续保留播放器限制。

## 录制与恢复

录制句柄提供 `result`、`stop()`、`cancel()`、VOD `pause()` / `resume()`、
`endInput(id)` 和 `restartInput(id, { generation, url? })`。
stop 排空已接受工作，cancel 中止；各输入独立结束和重启。Live/EVENT 不支持暂停。
`limits` 限制描述符、元数据、sample 和历史；`onEvent` 观察 Engine 状态、映射、gap、进度及输出。

Node 确定文件路径的下载和录制支持：

```ts
const resume = { directory: './jobs/video', durability: 'sync-all' as const };
const result = await node.download({ url, filename: 'video.mp4', resume });
const recording = node.startRecording({
  url,
  output: { type: 'file', path: './recording.mp4' },
  resume: { directory: './jobs/recording' },
  missingSegments: 'fail',
});
```

`durability` 为 `flush | sync-all`，默认 `sync-all`；flush 不承诺掉电持久性。
每个任务使用独占目录。schema-1 任务返回 `RESUME_INVALID` 并保留现场，不迁移、不清空。
Browser、Blob、借用 Writable 和任意文件工厂不支持恢复，Engine 恢复不能与转码或 aria2 组合。

修改已有输出前校验配置、输入/资源身份、稳定密钥版本、已提交前缀及完成分片。
配置、身份或版本冲突返回 `RESUME_CONFLICT`，损坏/旧格式返回 `RESUME_INVALID`，
重放证据缺失返回 `RESUME_REPLAY_REQUIRED`；具体原因保留在 `reason`。
finalizing/completed 恢复不会获取清单或重放媒体。
恢复分割的首文件为指定路径，后续为 `<path>.part-000001.mp4` 等。

加密恢复要求 `decryption.keyResolver` 返回稳定 `version`，不持久化原始密钥。
续期凭证通过 headers/provider 提供，不能修改媒体及密钥资源身份。
完成记录持久化前保留任务目录及引用的 partial。重放记录受 `limits.queuedMetadataBytes`
限制，超过预算明确失败。录制窗口淘汰默认 fail，可显式使用
`missingSegments: 'skip' | 'split'`；资源重写不属于窗口淘汰。

## 解密与能力查询

TS、fMP4、Packed AAC-LC 共用 Engine。支持资源 AES-128、TS AVC/AAC SAMPLE-AES、
Packed AAC SAMPLE-AES 及 fMP4 AVC/HEVC/AAC cenc/cbcs。
仍不支持 TS HEVC SAMPLE-AES、Packed AAC CTR、SAMPLE-AES/CTR/GCM WebVTT、LL-HLS partial segments
及任意密文切片。

`decryption.experimentalGcm: true` 显式开启上游实验性 draft-22 `AES-256-GCM`
完整资源格式：32 字节密钥、头部 16 字节 IV、尾部 16 字节认证 tag，默认关闭。
认证成功前不会提交该资源的明文或 sample。密钥长度错误为 `KEY_INVALID`，
认证失败为 `AUTHENTICATION_FAILED`。密钥请求 method 增加 `AES-256-GCM`。
不接受 AES-128 密钥、其他 GCM 布局、显式 IV tag 或任意字节范围。

```ts
const decision = await downloader.queryCapability({
  inputs: [
    {
      id: 'primary',
      container: 'fmp4',
      encryption: 'SAMPLE-AES-CTR',
      codecs: ['avc', 'aac-lc'],
      scheme: 'cenc',
    },
  ],
  output: 'writable',
  playbackTarget: 'direct-browser',
});
console.log(decision.containerSupported, decision.playbackSupported);
console.log(decision.rejections, decision.requirements);
```

查询仅依据声明的容器、编码、加密、输出、播放目标和恢复条件，不请求媒体，也不代替运行时验证。
`output` 支持 `blob`、`writable`、`file-mp4`、`file-fmp4`；可补充 `mode`、`range`、
`embeddedAudio`、`subtitles`、`decodeGaps`、`maxBytes`、`resume`、`experimentalGcm`。
容器支持不等于特定浏览器/播放器可播放。公开错误保留 input、generation、epoch、track、
sample 等可用结构化上下文，不包含密钥和请求凭证。

## 时间线映射与边车

`report.timelineMap` 是 schema-2 `HlsTimelineMap`，包含各输出/轨道的明确时间区间和
`complete` 标记，由保留的 Engine 映射、gap 和完成输出生成。
`historyEntries` 限制历史；截断、时间边界缺失或歧义会标记不完整，不承诺完整媒体索引。

```ts
const { report } = await downloader.downloadToWritable({ url }, writable);
const timelineMap = report!.timelineMap!;
const chapters = exportChapters({
  timelineMap,
  chapters: [
    {
      title: '开场',
      range: {
        start: { ticks: '0', timescale: 1 },
        end: { ticks: '5', timescale: 1 },
      },
    },
  ],
});
const subtitles = await downloader.downloadSubtitleOutputs({
  url,
  subtitle: { groupId: 'subs', name: 'English' },
  timelineMap,
});
```

两种导出均以 `SUBTITLE_INVALID` 拒绝不完整映射，按已知 range/gap/输出边界裁剪及拆分，
再转换为输出时钟。`track: { inputId, trackId }` 可显式选轨。
字幕边车只读取字幕资源，不重新读取主媒体；两种工具都不会自动写文件。
`downloadSubtitles()` 保留，通过 Engine 处理获取媒体时钟。
