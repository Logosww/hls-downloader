适配器专有字段通过 `HlsDownloader` 构造函数 `options` / `setOptions` 传入，或在单次 `download()` 调用中传入。与单次选项合并时，单次选项优先。

<Callout type="info" title="默认 Transmux">
  各适配器的**普通下载默认走 transmux/remux，不重编码**。BrowserAdapter 使用
  [hls-transmux](https://github.com/Logosww/hls-transmux) WebAssembly 做 transmux，使用 Mediabunny
  WebCodecs 做 `transcode`；NodeAdapter 仅在需要时初始化原生 FFmpeg。
</Callout>

## BrowserAdapter

```ts
import { BrowserAdapter } from '@hls-downloader/adapters/browser';
```

普通下载使用 [hls-transmux](https://github.com/Logosww/hls-transmux) WebAssembly。`download()` 返回经典 fast-start MP4；`downloadToStream()` 输出 fragmented MP4 分块。

转码使用 Mediabunny 与 WebCodecs，不依赖 `@ffmpeg/ffmpeg`。BrowserAdapter 支持 `h264`、`hevc`、`vp9` 预设及可选的 `videoBitrate`、`audioBitrate`。当前浏览器不支持所需编码器配置时会明确报错。

参考 CPU 微基准（8 分片 fixture，Chrome 150 / macOS，3 次中位数）：transmux 相对 Mediabunny remux 约 **5.0×**；H.264 转码相对多线程 `ffmpeg.wasm` 约 **2.2×**。详见[适配器指南](/zh/guide/adapters#性能参考)。

### `download()` 返回值

| 字段            | 类型     |
| --------------- | -------- |
| `blobURL`       | `string` |
| `totalSegments` | `number` |

### 浏览器媒体请求上下文

`options.browserRequest` 设置 BrowserAdapter 的实例默认值。`parseHls`、`getPosterUrl`、`download`、`downloadToStream` 和 `downloadToWritable` 均支持单次 `browserRequest`，其值**整体替换实例配置**。传入 `{}` 使用原生 fetch 默认值；省略则继承实例配置。NodeAdapter 不支持此选项。

可选的 `fetch(url, init): Promise<Response>` 只负责**一次传输**，可在发送前异步准备扩展上下文。参数包含真实 URL、现有请求头（含 Range）、凭据选项及取消信号。返回标准 Response，保留状态码、响应头、流式响应体和最终 URL；准备、传输和响应体消费均须响应取消。没有最终 URL 的合成响应使用请求 URL 解析相对资源。库继续管理重试，读取失败时丢弃不完整内容，取消后丢弃迟到结果；不要在适配函数内叠加重试循环。

封面、转码等全部媒体读取均使用该传输；WASM 继续使用独立的本地资源加载器。未配置时保持原生 fetch 和凭据默认行为。HTTP 401/403 保留状态信息且不重试，网络失败和取消可区分。封面网络失败现在抛出结构化错误，无可解码视频时仍返回 `undefined`。

每次操作固定请求配置和请求头。浏览器播放列表和封面结果**不在公开调用之间缓存**，同实例也不复用；登录态变化在下次调用生效。保留 `clearCache()`，对 BrowserAdapter 为 no-op。因此重复解析或取封面会重新请求。传输函数闭包中的上下文仍须由调用方保证在操作期间稳定。

```ts
import { HlsDownloader } from '@logosw/hls-downloader/core';
import { BrowserAdapter } from '@logosw/hls-downloader/adapters/browser';

const mediaOrigin = 'https://media.example.com';
const downloader = new HlsDownloader({
  adapter: BrowserAdapter,
  options: {
    browserRequest: {
      credentials: 'include',
      async fetch(url, init) {
        const trusted = new URL(url).origin === mediaOrigin;
        const headers = new Headers(init.headers);
        if (trusted) headers.set('Authorization', 'Bearer <token>');
        init.signal?.throwIfAborted();
        return fetch(url, {
          ...init,
          headers,
          credentials: trusted ? init.credentials : 'omit',
          redirect: 'error',
        });
      },
    },
  },
});

await downloader.parseHls({ url: mediaOrigin + '/video.m3u8' });
await downloader.parseHls({ url: mediaOrigin + '/public.m3u8', browserRequest: {} });
```

示例仅向指定来源提供凭据并拒绝重定向。允许重定向的应用须自行实施目标域策略；原生 fetch 不会让回调观察每一个中间跳转。现有显式 `headers` 仍按原契约用于媒体请求，因此按目标域变化的凭据应在传输函数中设置，不宜放入全局请求头。

扩展负责权限、网页和标签页关联、异步请求规则准备及清理。普通请求头无法可靠重放 Cookie、Referer 和 Origin；浏览器 Cookie 策略、分区 Cookie 和站点授权仍可能阻止下载。库不读取浏览器 Cookie，不安装 Chrome 专属规则。不要记录凭据或将其放入异常消息。

WXT Manifest V3 页面应从公开的 `/core` 和 `/adapters/browser` 子路径导入。生产构建将包内 WASM 打包为本地资源；扩展 CSP 需允许 `script-src 'self' 'wasm-unsafe-eval'`。WASM 初始化独立于媒体传输，不接收站点凭据；验收构建无需资源路径覆盖接口。

## NodeAdapter

```ts
import { NodeAdapter } from '@hls-downloader/adapters/node';
```

普通下载走**原生 transmux 路径**。**不会初始化原生 FFmpeg**，除非满足下方 FFmpeg 场景。

### 何时加载 FFmpeg

| API              | 加载 FFmpeg？  | 条件                                                                                |
| ---------------- | -------------- | ----------------------------------------------------------------------------------- |
| `parseHls()`     | 否             | —                                                                                   |
| `init()`         | 否             | —                                                                                   |
| `download()`     | **否**（默认） | 省略 `transcode` / `globalOptions.transcode` 且未启用 `aria2.enabled` → 仅 transmux |
| `download()`     | **是**         | 设置 `transcode` 选项对象、`globalOptions.transcode`，**或** `aria2.enabled: true`  |
| `getPosterUrl()` | **视情况**     | 仅当轻量分片提取失败、需要 FFmpeg 回退时                                            |

### `download()` 返回值

| 字段            | 类型     |
| --------------- | -------- |
| `filePath`      | `string` |
| `totalSegments` | `number` |

### 适配器专有选项

| 字段    | 类型     |
| ------- | -------- |
| `aria2` | `object` |

分片下载默认使用内置 HTTP；将 `aria2.enabled` 设为 `true` 后改用 [aria2](https://aria2.github.io/)（`aria2c` CLI + 会话输入文件）。

`aria2.enabled` 为 `true` 时需安装 aria2。自定义请求头会写入 aria2 会话文件（每条 URI 下 `header=Name: value`）。

#### `aria2` 对象（`NodeAdapterAria2Options`）

| 字段                     | 类型       |
| ------------------------ | ---------- |
| `enabled`                | `boolean`  |
| `path`                   | `string`   |
| `maxConcurrentDownloads` | `number`   |
| `maxConnectionPerServer` | `number`   |
| `split`                  | `number`   |
| `minSplitSize`           | `string`   |
| `extraArgs`              | `string[]` |

未传 `maxConcurrentDownloads` 时，实际并发数跟随每次 `download()` 的 `downloadConcurrency`（或 `globalOptions.download.concurrency`）。

### 平台支持

原生模块必须匹配你的操作系统和 Node.js ABI。常见平台已发布预构建二进制文件。

## Writable output

| Capability          | Browser | Node |
| ------------------- | ------- | ---- |
| `writableOutput`    | true    | true |
| `alternateAudio`    | true    | true |
| `subtitleExport`    | true    | true |
| `resumableDownload` | false   | true |

使用 `downloadToWritable()` 获得有界媒体缓冲与异步写入目标。现有回调流式接口行为不变。

Node 恢复下载使用单次调用选项 `resume: { directory }`，仅支持普通 VOD 文件输出，不能与转码、启用的 aria2 或流式 API 组合。详见[恢复下载](./hls-downloader)。

## AES-128 VOD

带初始音视频偏移的外置音轨合流，已验证文件/Blob 播放。Chromium MSE 会忽略前置空 edit；接入 MSE 时，播放端必须分别映射各轨道时间戳，不能将这些合流字节原样追加到单个 SourceBuffer。SDK 不提供该 MSE 映射。

BrowserAdapter 和 NodeAdapter 会自动识别选中媒体清单中的 AES-128。支持有限 TS/fMP4 VOD、AVC/HEVC 视频和 AAC-LC 音频，包含明密切换、密钥轮换、加密 MAP 和一条选中的外置音轨。`download()` 输出 classic MP4；callback stream 和 writable 输出 fMP4。浏览器播放仍取决于设备的编解码器支持。

默认 identity/version-1 key 与媒体共用 headers、重试、取消以及 Browser 的 `browserRequest` transport/credentials。key 必须恰好 16 字节；响应读取上限为 17 字节，非法长度不会重试。

```ts
await downloader.downloadToWritable(
  {
    url: 'https://example.com/video.m3u8',
    decryption: {
      keyResolver: async (request) => {
        const response = await fetch(request.uri, { signal: request.signal });
        if (!response.ok) throw new Error('Key request failed');
        return { key: new Uint8Array(await response.arrayBuffer()), expiresInMs: 60_000 };
      },
    },
  },
  writable,
);
```

`decryption` 是 download、stream、writable 的单次操作选项：

| 字段 | 契约 |
| --- | --- |
| `keyResolver` | 替代 HTTP provider。返回 `{ key: Uint8Array, version?: string, expiresInMs?: number }` 或 `null`。只有 `null` 允许尝试其他已声明 KEYFORMAT 候选；throw/reject 会安全失败，不暴露其消息，不自动回退 HTTP。 |
| `keyFormats` | 有序的 `{ format: string, versions: readonly number[] }[]`，默认 identity/version 1；自定义格式须显式声明。 |
| `encryptedRanges` | 默认 `'reject'`。`'complete-resources'` 表示调用者确认每个 range 都是独立完整加密且填充的资源；响应须为 206，Content-Range 和长度须完全匹配。 |
| `limits` | 正安全整数，默认值见下文；限制 source 读取，不等于进程或 Blob 总内存上限。 |

resolver 请求包含 `operationId`、`inputId`、`resourceKind`、`uri`、`method`、`keyFormat`、`keyFormatVersions`、`originalSequence`、`epoch`、`generation`、`declaration`、`resolveRevision`、`refreshGeneration`、`refreshReason` 及独立请求的 `signal`。协议大整数为十进制字符串。`expiresInMs` 是非负安全整数的相对有效期，0 表示立即过期。取消会中止待处理 resolver 请求并丢弃迟到结果；即使 `operationId` 相同，不同操作也不共享 key 缓存。

默认 `limits`：`manifestBytes = 4 MiB`、`resourceBytes = 16 MiB`、`waitingBytes = 32 MiB`、`resources = 2`、`keyRequests = 2`、`cachedKeys = 8`、`keyWaiters = 2`。`waitingBytes` 至少等于 `resourceBytes`。普通下载选择清单时也受 manifest 上限约束；大型有限清单可提高 `manifestBytes`。显式配置 `decryption` 时，明文输入也会进入结构化有限输入路径；`resources` 控制该路径的并发，原有明文路径继续使用 `downloadConcurrency`。

`capabilities.aes128` 表示上述有限能力，`capabilities.decryption` 描述 method、container、codec、外置音频及不支持加密恢复的边界。Live/EVENT、discontinuity、sample encryption/GCM、加密 resume、转码、aria2 和加密 WebVTT 暂不支持。清单已知的不支持组合在 key/media 工作前拒绝；容器和编码验证需要读取媒体。

错误区分 `KEY_UNAVAILABLE`、`KEY_RESOLUTION_FAILED`、`KEY_INVALID`、`KEY_EXPIRED`、`ENCRYPTION_INVALID`、`DECRYPT_FAILED`、`MEDIA_INVALID` 和 `RESOURCE_LIMIT_EXCEEDED`。CBC 不提供认证，不保证所有错误 key 都可检测。公共错误和事件不包含 resolver 消息、key bytes 或 key version。

`DECRYPTION_PROGRESS` 的 `payload.decryption` 提供各输入 discovered/committed 计数，以及分开的 media/MAP downloaded、decrypted、ready 计数，均为十进制字符串。明文资源不增加 decrypted 计数，committed 不是恢复 checkpoint。只有目标成功 close 后才发出公共完成事件。
