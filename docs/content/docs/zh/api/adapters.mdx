适配器专有字段通过 `HlsDownloader` 构造函数 `options` / `setOptions` 传入，或在单次 `download()` 调用中传入。与单次选项合并时，单次选项优先。

<Callout type="info" title="默认 Transmux">
  各适配器的**普通下载默认走 transmux/remux，不重编码**。BrowserAdapter 使用
  [hls-engine](https://github.com/Logosww/hls-engine) WebAssembly 做 transmux，使用 Mediabunny
  WebCodecs 做 `transcode`；NodeAdapter 使用本机 FFmpeg 命令进行转码。
</Callout>

## BrowserAdapter

```ts
import { BrowserAdapter } from '@hls-downloader/adapters/browser';
```

普通下载使用 [hls-engine](https://github.com/Logosww/hls-engine) WebAssembly。`download()` 返回经典 fast-start MP4；`downloadToStream()` 输出 fragmented MP4 分块。

转码使用 Mediabunny 与 WebCodecs，不依赖 `@ffmpeg/ffmpeg`。BrowserAdapter 支持 `h264`、`hevc`、`vp9` 预设及可选的 `videoBitrate`、`audioBitrate`。当前浏览器不支持所需编码器配置时会明确报错。

参考 CPU 微基准（8 分片 fixture，Chrome 150 / macOS，3 次中位数）：transmux 相对 Mediabunny remux 约 **5.0×**；H.264 转码相对多线程 `ffmpeg.wasm` 约 **2.2×**。详见[适配器指南](/zh/guide/adapters#性能参考)。

### `download()` 返回值

| 字段            | 类型     |
| --------------- | -------- |
| `blobURL`       | `string` |
| `totalSegments` | `number` |

### 浏览器媒体请求上下文

`options.browserRequest` 设置 BrowserAdapter 的实例默认值。`parseHls`、`getPosterUrl`、`download`、`downloadToStream` 和 `downloadToWritable` 均支持单次 `browserRequest`，其值**整体替换实例配置**。传入 `{}` 使用原生 fetch 默认值；省略则继承实例配置。NodeAdapter 不支持此选项。

可选的 `fetch(url, init): Promise<Response>` 只负责**一次传输**，可在发送前异步准备扩展上下文。参数包含真实 URL、现有请求头（含 Range）、凭据选项及取消信号。返回标准 Response，保留状态码、响应头、流式响应体和最终 URL；准备、传输和响应体消费均须响应取消。没有最终 URL 的合成响应使用请求 URL 解析相对资源。库继续管理重试，读取失败时丢弃不完整内容，取消后丢弃迟到结果；不要在适配函数内叠加重试循环。

封面、转码等全部媒体读取均使用该传输；WASM 继续使用独立的本地资源加载器。未配置时保持原生 fetch 和凭据默认行为。HTTP 401/403 保留状态信息且不重试，网络失败和取消可区分。封面网络失败现在抛出结构化错误，无可解码视频时仍返回 `undefined`。

每次操作固定请求配置和请求头。浏览器播放列表和封面结果**不在公开调用之间缓存**，同实例也不复用；登录态变化在下次调用生效。保留 `clearCache()`，对 BrowserAdapter 为 no-op。因此重复解析或取封面会重新请求。传输函数闭包中的上下文仍须由调用方保证在操作期间稳定。

```ts
import { HlsDownloader } from '@logosw/hls-downloader/core';
import { BrowserAdapter } from '@logosw/hls-downloader/adapters/browser';

const mediaOrigin = 'https://media.example.com';
const downloader = new HlsDownloader({
  adapter: BrowserAdapter,
  options: {
    browserRequest: {
      credentials: 'include',
      async fetch(url, init) {
        const trusted = new URL(url).origin === mediaOrigin;
        const headers = new Headers(init.headers);
        if (trusted) headers.set('Authorization', 'Bearer <token>');
        init.signal?.throwIfAborted();
        return fetch(url, {
          ...init,
          headers,
          credentials: trusted ? init.credentials : 'omit',
          redirect: 'error',
        });
      },
    },
  },
});

await downloader.parseHls({ url: mediaOrigin + '/video.m3u8' });
await downloader.parseHls({ url: mediaOrigin + '/public.m3u8', browserRequest: {} });
```

示例仅向指定来源提供凭据并拒绝重定向。允许重定向的应用须自行实施目标域策略；原生 fetch 不会让回调观察每一个中间跳转。现有显式 `headers` 仍按原契约用于媒体请求，因此按目标域变化的凭据应在传输函数中设置，不宜放入全局请求头。

扩展负责权限、网页和标签页关联、异步请求规则准备及清理。普通请求头无法可靠重放 Cookie、Referer 和 Origin；浏览器 Cookie 策略、分区 Cookie 和站点授权仍可能阻止下载。库不读取浏览器 Cookie，不安装 Chrome 专属规则。不要记录凭据或将其放入异常消息。

WXT Manifest V3 页面应从公开的 `/core` 和 `/adapters/browser` 子路径导入。生产构建将包内 WASM 打包为本地资源；扩展 CSP 需允许 `script-src 'self' 'wasm-unsafe-eval'`。WASM 初始化独立于媒体传输，不接收站点凭据；验收构建无需资源路径覆盖接口。

## NodeAdapter

```ts
import { NodeAdapter } from '@hls-downloader/adapters/node';
```

普通下载走**原生 transmux 路径**。**不会初始化原生 FFmpeg**，除非满足下方 FFmpeg 场景。

### 何时加载 FFmpeg

| API              | 加载 FFmpeg？  | 条件                                                                                |
| ---------------- | -------------- | ----------------------------------------------------------------------------------- |
| `parseHls()`     | 否             | —                                                                                   |
| `init()`         | 否             | —                                                                                   |
| `download()`     | **否**（默认） | 省略 `transcode` / `globalOptions.transcode` 且未启用 `aria2.enabled` → 仅 transmux |
| `download()`     | **是**         | 设置 `transcode` 选项对象、`globalOptions.transcode`，**或** `aria2.enabled: true`  |
| `getPosterUrl()` | **视情况**     | 仅当轻量分片提取失败、需要 FFmpeg 回退时                                            |

### `download()` 返回值

| 字段            | 类型     |
| --------------- | -------- |
| `filePath`      | `string` |
| `totalSegments` | `number` |

### 适配器专有选项

| 字段    | 类型     |
| ------- | -------- |
| `aria2` | `object` |

分片下载默认使用内置 HTTP；将 `aria2.enabled` 设为 `true` 后改用 [aria2](https://aria2.github.io/)（`aria2c` CLI + 会话输入文件）。

`aria2.enabled` 为 `true` 时需安装 aria2。自定义请求头会写入 aria2 会话文件（每条 URI 下 `header=Name: value`）。

#### `aria2` 对象（`NodeAdapterAria2Options`）

| 字段                     | 类型       |
| ------------------------ | ---------- |
| `enabled`                | `boolean`  |
| `path`                   | `string`   |
| `maxConcurrentDownloads` | `number`   |
| `maxConnectionPerServer` | `number`   |
| `split`                  | `number`   |
| `minSplitSize`           | `string`   |
| `extraArgs`              | `string[]` |

未传 `maxConcurrentDownloads` 时，实际并发数跟随每次 `download()` 的 `downloadConcurrency`（或 `globalOptions.download.concurrency`）。

### 平台支持

原生模块必须匹配你的操作系统和 Node.js ABI。常见平台已发布预构建二进制文件。

## 统一 Engine 输出

所有 HLS 下载、流式输出、时间线及录制入口统一使用 `hls-engine 1.0.2`，保留现有方法名。
FFmpeg/WebCodecs 仍负责独立的转码路径。有限下载要求每个选定输入均有 ENDLIST；
`startRecording()` 和 `startMultiTrackRecording()` 支持 Live/EVENT 清单刷新。

转封装和录制结果通过 `report: HlsEngineReport` 返回输入进度、轨道、字幕回执、完成输出、请求/实际区间、
有界映射及历史截断标记。协议计数、generation、sequence 和 ticks 保持十进制字符串，
精确运算使用 `BigInt`。已移除 `timelineReport` 及完整资源/sample 索引契约。

`download()` 默认选择外部默认音轨，也可用 `audio` 指定。
`downloadMultiTrack()` 显式传入 `embeddedAudio: 'keep' | 'exclude'`，并支持
`audioTracks`、`subtitleTracks` 和 `playbackTarget`；不会读取未选中的 rendition。
`parseMediaPlaylist(text, url)` 无网络解析无损元数据，`parseHls()` 继续提供选流及选轨信息。

Browser `download({ url, maxBytes? })` 的默认收集上限为 **256 MiB**。
录制的 `{ type: 'blob', maxBytes }` 必须显式指定容量。容量限制收集字节，不是进程总内存上限，
也不包括 classic MP4 索引的全部开销。Writable 逐次等待 write 和 close；
callback `downloadToStream()` 不等待回调返回的 Promise。

`downloadOutputs()` 返回 `{ operationId, totalSegments, outputs, report }`。
Browser 返回 fMP4 Blob URL，Node 返回 classic MP4，文件名依次为
`basename.001.mp4`、`basename.002.mp4`。Blob URL 用后需 revoke。
`downloadToWritables()` 使用工厂获取每个 sink；分割通过 `timeline.changePolicy: 'split'`
开启，单个借用 Writable 不能分割。失败的 `error.completedOutputs` 保留已发布文件及
已成功关闭的 Writable。READY/result 完成必须等待目标关闭。

## 选轨 VOD 转码

`download({ url, audio?, decryption?, timeline?, transcode: { preset } })` 支持
`h264`、`hevc`、`vp9`，可使用默认或显式选择的单条外置音轨。
Engine 先完成选轨、解密和可解码范围处理，生成明文 fMP4，再交给 Node FFmpeg
或 Browser WebCodecs 编码。范围可能扩展至随机访问边界，不是精确到帧裁切。
不会读取未选中的 rendition。结果保留 `totalSegments` 和文件/Blob URL，但不返回
`report`，因为中间 remux 报告不能代表最终编码产物。

Browser 按实际编码器/解码器能力检查所有选定轨道；不支持时返回 `UNSUPPORTED_OUTPUT`，
不会静默丢弃音频。`maxBytes` 默认 256 MiB，分别限制中间媒体和转码输出，非总内存限制。
Node 需要 PATH 中的 `ffmpeg` 可执行文件，保留已存在的目标文件；成功、失败、取消均清理
临时文件，完成等待编码器退出及最终输出发布。

多音轨容器转码、字幕烧录、录制、恢复、split 和流式转码仍不支持。
`queryCapability()` 查询 Engine remux/录制组合，不查询编码器可用性；
`transcodePresets` 列出候选预设，实际支持在转换时检查。

## 持续 WebVTT sidecar

`downloadMultiTrack()` 和 `startMultiTrackRecording()` 支持明文及 AES-128 WebVTT
segment/MAP，包括密钥轮换和原始 sequence IV。字幕与媒体共用 operation 的 key session、
取消及资源预算。SAMPLE-AES、CTR、GCM WebVTT 仍不支持；持续路径仅支持纯文本与标准
cue settings，不支持样式块及富文本 cue 标记。

```ts
const session = downloader.startMultiTrackRecording({
  url,
  embeddedAudio: 'keep',
  subtitleTracks: [{
    id: 'english',
    selector: { groupId: 'subs', name: 'English' },
    embedded: false,
    sidecar: { type: 'writable', writable: subtitleWritable },
  }],
  output: { type: 'writable', writable: mediaWritable },
  onEvent(event) {
    if (event.type === 'subtitleCommit') console.log(event.commit.frontiers);
  },
});
// 需要结束时：session.stop(); await session.result;
```

两端均等待字幕 write 和 close。`embedded` 默认 `true`；设为 `false` 时必须提供 sidecar，
容器不再内嵌 wvtt。拆分时，为每条字幕选择提供
`{ type: 'writables', acquire: async ({ inputId, outputIndex }) => writable }`。
各 writer 必须与媒体及其他活动字幕 writer 独立；前一分卷关闭后才获取下一分卷。
单个借用 Writable 不支持 split。

每个输出写入一次 UTF-8 `WEBVTT` 头。cue 使用实际提交的输出时间轴，随范围裁切和分卷重定位，
跨提交窗口的 cue 可分段输出。时间戳向下取整到毫秒，量化后为空的片段不输出。
`subtitleCommit` 提供精确有理数时间、receipt、轨道/输入、generation/epoch、分卷、裁切或拒绝
结果及提交水位。该事件仅用于观察；回调返回值不提供背压或持久化确认，确认由 sidecar sink
完成。stop 排空已接受工作；cancel 不等待不响应的 sink，迟到写入不会把取消变为成功。
写入/关闭失败返回 `OUTPUT_WRITE_FAILED`；已经确认写入的 Writable 字节不能回滚。

Node 的固定媒体文件输出还支持 `sidecar: { type: 'file', path: './english.vtt' }`。
启用 `resume: { directory: './job' }` 时，每条选中字幕均须配置固定 sidecar 文件；
Writable/工厂不能恢复。保留已有的无关文件。首个输出使用指定路径，后续使用
`<path>.part-000001.vtt`，与媒体的 `.part-000001.mp4` 分卷对应。
发布逐文件完成，不承诺多个文件的原子重命名。

本库的 checkpoint 外层仍为 schema 2；媒体/字幕联合恢复使用 Engine 内层 archive schema 3，
仅媒体 archive 仍为 schema 2。截去未提交尾部前，校验全部已提交前缀并重新读取字幕资源。
加密恢复要求 key resolver 提供稳定 `version`。目标路径/配置变更返回 `RESUME_CONFLICT`，
前缀损坏返回 `RESUME_INVALID`；重放资源或密钥版本缺失/变更可能返回
`RESUME_REPLAY_REQUIRED`。不持久化原始密钥；完成态可离线恢复。
完成态持久化前保留任务目录及 partial 文件。字幕重放元数据共用有界恢复日志
（`limits.queuedMetadataBytes`），耗尽返回 `RESOURCE_LIMIT_EXCEEDED`，不承诺无限恢复历史。

`downloadSubtitles()` 和 `downloadSubtitleOutputs()` 同时支持 `decryption` 和 `maxBytes`
（收集的 UTF-8 字幕数据默认上限 16 MiB）。后者使用调用方提供的完整 timeline map，
只读取字幕资源。这两个有限导出接口本身不启用持续录制。
`capabilities.multiTrack` 的 `subtitleResources`、`subtitleSidecars` 描述新增能力；
`queryCapability()` 请求中的 `subtitles` 指内嵌字幕，继续保留播放器限制。

## 录制与恢复

录制句柄提供 `result`、`stop()`、`cancel()`、VOD `pause()` / `resume()`、
`endInput(id)` 和 `restartInput(id, { generation, url? })`。
stop 排空已接受工作，cancel 中止；各输入独立结束和重启。Live/EVENT 不支持暂停。
`limits` 限制描述符、元数据、sample 和历史；`onEvent` 观察 Engine 状态、映射、gap、进度及输出。

Node 确定文件路径的下载和录制支持：

```ts
const resume = { directory: './jobs/video', durability: 'sync-all' as const };
const result = await node.download({ url, filename: 'video.mp4', resume });
const recording = node.startRecording({
  url,
  output: { type: 'file', path: './recording.mp4' },
  resume: { directory: './jobs/recording' },
  missingSegments: 'fail',
});
```

`durability` 为 `flush | sync-all`，默认 `sync-all`；flush 不承诺掉电持久性。
每个任务使用独占目录。schema-1 任务返回 `RESUME_INVALID` 并保留现场，不迁移、不清空。
Browser、Blob、借用 Writable 和任意文件工厂不支持恢复，Engine 恢复不能与转码或 aria2 组合。

修改已有输出前校验配置、输入/资源身份、稳定密钥版本、已提交前缀及完成分片。
配置、身份或版本冲突返回 `RESUME_CONFLICT`，损坏/旧格式返回 `RESUME_INVALID`，
重放证据缺失返回 `RESUME_REPLAY_REQUIRED`；具体原因保留在 `reason`。
finalizing/completed 恢复不会获取清单或重放媒体。
恢复分割的首文件为指定路径，后续为 `<path>.part-000001.mp4` 等。

加密恢复要求 `decryption.keyResolver` 返回稳定 `version`，不持久化原始密钥。
续期凭证通过 headers/provider 提供，不能修改媒体及密钥资源身份。
完成记录持久化前保留任务目录及引用的 partial。重放记录受 `limits.queuedMetadataBytes`
限制，超过预算明确失败。录制窗口淘汰默认 fail，可显式使用
`missingSegments: 'skip' | 'split'`；资源重写不属于窗口淘汰。

## 解密与能力查询

TS、fMP4、Packed AAC-LC 共用 Engine。支持资源 AES-128、TS AVC/AAC SAMPLE-AES、
Packed AAC SAMPLE-AES 及 fMP4 AVC/HEVC/AAC cenc/cbcs。
仍不支持 TS HEVC SAMPLE-AES、Packed AAC CTR、SAMPLE-AES/CTR/GCM WebVTT、LL-HLS partial segments
及任意密文切片。

`decryption.experimentalGcm: true` 显式开启上游实验性 draft-22 `AES-256-GCM`
完整资源格式：32 字节密钥、头部 16 字节 IV、尾部 16 字节认证 tag，默认关闭。
认证成功前不会提交该资源的明文或 sample。密钥长度错误为 `KEY_INVALID`，
认证失败为 `AUTHENTICATION_FAILED`。密钥请求 method 增加 `AES-256-GCM`。
不接受 AES-128 密钥、其他 GCM 布局、显式 IV tag 或任意字节范围。

```ts
const decision = await downloader.queryCapability({
  inputs: [
    {
      id: 'primary',
      container: 'fmp4',
      encryption: 'SAMPLE-AES-CTR',
      codecs: ['avc', 'aac-lc'],
      scheme: 'cenc',
    },
  ],
  output: 'writable',
  playbackTarget: 'direct-browser',
});
console.log(decision.containerSupported, decision.playbackSupported);
console.log(decision.rejections, decision.requirements);
```

查询仅依据声明的容器、编码、加密、输出、播放目标和恢复条件，不请求媒体，也不代替运行时验证。
`output` 支持 `blob`、`writable`、`file-mp4`、`file-fmp4`；可补充 `mode`、`range`、
`embeddedAudio`、`subtitles`、`decodeGaps`、`maxBytes`、`resume`、`experimentalGcm`。
容器支持不等于特定浏览器/播放器可播放。公开错误保留 input、generation、epoch、track、
sample 等可用结构化上下文，不包含密钥和请求凭证。

## 时间线映射与边车

`report.timelineMap` 是 schema-2 `HlsTimelineMap`，包含各输出/轨道的明确时间区间和
`complete` 标记，由保留的 Engine 映射、gap 和完成输出生成。
`historyEntries` 限制历史；截断、时间边界缺失或歧义会标记不完整，不承诺完整媒体索引。

```ts
const { report } = await downloader.downloadToWritable({ url }, writable);
const timelineMap = report!.timelineMap!;
const chapters = exportChapters({
  timelineMap,
  chapters: [
    {
      title: '开场',
      range: {
        start: { ticks: '0', timescale: 1 },
        end: { ticks: '5', timescale: 1 },
      },
    },
  ],
});
const subtitles = await downloader.downloadSubtitleOutputs({
  url,
  subtitle: { groupId: 'subs', name: 'English' },
  timelineMap,
});
```

两种导出均以 `SUBTITLE_INVALID` 拒绝不完整映射，按已知 range/gap/输出边界裁剪及拆分，
再转换为输出时钟。`track: { inputId, trackId }` 可显式选轨。
字幕边车只读取字幕资源，不重新读取主媒体；两种工具都不会自动写文件。
`downloadSubtitles()` 保留，通过 Engine 处理获取媒体时钟。
